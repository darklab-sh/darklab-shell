# Headless API and CLI

darklab_shell exposes a small `/api/v1` surface for scripts, CI jobs, and local terminals that need to start runs or read saved data without opening the browser UI. The API uses the same session token, command validation, brokered run lifecycle, artifact storage, project query services, and shared per-IP rate-limit policy as the browser run routes.

The bundled `darklab` CLI is a thin wrapper around this API. Install it from the repo root with:

```bash
python -m pip install ./tools/darklab_cli
```

Then point it at a running instance:

```bash
export DARKLAB_API_URL=http://localhost:8888
export DARKLAB_TOKEN=tok_your_session_token
darklab whoami
```

---

## Auth

Use a session token generated by the browser or the `session-token` command.

```bash
curl -H "Authorization: Bearer tok_your_session_token" \
  http://localhost:8888/api/v1/whoami
```

`Authorization: Bearer tok_...` is the canonical header. `X-Session-ID: tok_...` is accepted as a compatibility fallback. Anonymous UUID sessions are rejected on `/api/v1/*`, and revoked or unknown tokens return a normal JSON error.

Errors use one shape:

```json
{
  "error": {
    "code": "missing_token",
    "message": "API token is required."
  }
}
```

Other authentication failures use the same envelope: malformed `Authorization` headers return
`invalid_authorization_header`, anonymous UUID sessions return `invalid_token`, and revoked or
unknown `tok_...` values return `revoked_token`.

## Versioning

`/api/v1` is additive within v1. Existing routes, required request fields, and documented response fields should not be removed or changed incompatibly. Breaking changes belong under a future `/api/v2`.

The OpenAPI contract is served at `/api/v1/openapi.json` and checked in at `docs/api-v1-openapi.json`. It includes route-level parameters plus request, response, error, and stream schemas for the public API. The Python spec in `app/services/api_v1/openapi.py` is the source of truth; regenerate the checked-in JSON with:

```bash
python scripts/generate_api_openapi.py
```

## Common Shapes

List routes use the same offset envelope as the browser's paged project views:

```json
{
  "runs": [],
  "total": 0,
  "limit": 50,
  "offset": 0,
  "has_more": false
}
```

Run summaries include browser-owned counts in one batched query path, including `artifact_count`, `finding_count`, `label_count`, `note_count`, `atlas_entity_count`, and `atlas_finding_count`. History search routes through the same backend-aware search clauses used by the browser, so SQLite FTS, Postgres trigram search, and offloaded-output fallback stay aligned.

History `since` and `until` filters must be ISO 8601 datetimes, such as `2026-05-19T00:00:00Z`. Invalid datetime filters return `400` with the same JSON error envelope as the rest of the API.

## Routes

| Method | Route | Purpose |
| --- | --- | --- |
| `GET` | `/api/v1/health` | Unauthenticated liveness check. |
| `GET` | `/api/v1/openapi.json` | Unauthenticated OpenAPI document. |
| `GET` | `/api/v1/whoami` | Token smoke test with creation metadata and the current successful-auth timestamp, without echoing the token. |
| `GET` | `/api/v1/history` | Current-token run history with `limit`, `offset`, `project_id`, `q`, `since`, `until`, `run_kind`, and `exit_code` filters. |
| `GET` | `/api/v1/history/<run_id>` | One current-token run summary. |
| `GET` | `/api/v1/history/<run_id>/output` | Text output by default, or JSON with `?format=json`. |
| `GET` | `/api/v1/history/<run_id>/artifacts` | Workspace artifact metadata for one run. |
| `GET` | `/api/v1/history/<run_id>/artifacts/<artifact_id>` | Download one artifact by stable artifact id. |
| `GET` | `/api/v1/projects` | Read-only project list. |
| `GET` | `/api/v1/projects/<project_id>` | Read-only project detail. |
| `GET` | `/api/v1/projects/<project_id>/findings` | Read-only project finding page. |
| `GET` | `/api/v1/projects/<project_id>/packages` | Read-only evidence package page. |
| `POST` | `/api/v1/runs` | Start a non-interactive command run. |
| `GET` | `/api/v1/runs/<run_id>` | Active or completed run status. |
| `GET` | `/api/v1/runs/<run_id>/stream` | SSE stream by default, or NDJSON with `?format=ndjson`. |
| `POST` | `/api/v1/runs/<run_id>/cancel` | Cancel an active current-token run, including browser-started runs. |

All run, history, artifact, and project routes are scoped to the token session. Cross-session IDs return `404` rather than confirming the object exists elsewhere.

## Running Commands

Start a run:

```bash
curl -sS -H "Authorization: Bearer $DARKLAB_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"command":"ping -c 4 darklab.sh"}' \
  "$DARKLAB_API_URL/api/v1/runs"
```

Start and follow from the CLI:

```bash
darklab run "ping -c 4 darklab.sh"
darklab run "ping -c 4 darklab.sh" --format ndjson
```

`POST /api/v1/runs` accepts:

```json
{
  "command": "nmap -p 80 example.com",
  "project_id": null,
  "workspace_cwd": ""
}
```

`project_id` is optional. When supplied, the completed external run is linked to that project. When omitted, API-started real commands honor the same active-project capture preference as browser-started real commands, including target discovery and generated Atlas entity linking preferences.

Workspace-aware command file flags use the server-side session workspace, not the CLI machine's current directory. Relative values such as `-o output.txt` and root-style values such as `-o /output.txt` both resolve inside the session workspace; packaged absolute paths such as SecLists wordlists remain available for read flags.

Interactive PTY commands are intentionally outside v1 and return `409 interactive_pty_not_supported` when the configured PTY trigger flag is present.

Real command starts return `status: "running"`. Built-in and missing-runtime synthetic runs finish immediately, so their start response can return `succeeded`, `failed`, or `complete` instead.

If the run broker is unavailable, the API returns `503 broker_unavailable` with `Retry-After: 5`.

## Streaming

SSE is the default stream format:

```bash
curl -N -H "Authorization: Bearer $DARKLAB_TOKEN" \
  "$DARKLAB_API_URL/api/v1/runs/$RUN_ID/stream"
```

NDJSON is available for shell pipelines:

```bash
curl -N -H "Authorization: Bearer $DARKLAB_TOKEN" \
  "$DARKLAB_API_URL/api/v1/runs/$RUN_ID/stream?format=ndjson"
```

SSE streams send `: heartbeat` comments during idle periods so proxies and clients do not treat a quiet scan as a dead connection. NDJSON framing uses `\n` line endings and emits one broker event object per line; during the same idle periods it emits `{"type":"heartbeat"}` rows. Each broker event includes `event_id` when the replay layer provides one, so scripts can resume with the last seen id. Reattach supports both `Last-Event-ID` and `?after=`, with `?after=` taking priority so CLI retries can be explicit. Streams end when the broker emits a terminal event such as `exit`, `killed`, or `error`. If the API layer catches a stream error while adapting to NDJSON, it writes one final `{"event":"error","code":"stream_error","message":"..."}` line before closing.

## CLI Commands

The CLI talks only to `/api/v1` and has no Flask app imports.

| Command | Purpose |
| --- | --- |
| `darklab whoami` | Check token auth. |
| `darklab run "<cmd>" [--project PROJECT_ID] [--follow\|--no-follow] [--format text\|json\|ndjson]` | Start a run. The default `--follow --format text` follows output as text, `--format ndjson` follows broker events, and `--no-follow --format json` prints the start payload. `--format json` is start-only, and `--format ndjson` is follow-only. Follow modes exit with code `2` if the stream closes before a terminal event. |
| `darklab tail <run_id> [--format text\|ndjson] [--after EVENT_ID]` | Follow an existing run stream. Exits with code `2` if the stream closes before a terminal event. |
| `darklab cancel <run_id>` | Cancel an active run in the same token session. |
| `darklab history [--project PROJECT_ID] [--since ISO] [--until ISO] [--limit N] [--offset N] [--format text\|json\|ndjson]` | Read paged history. CLI output includes each run's finished timestamp and prints the newest item last. |
| `darklab show <run_id> [--lines N] [--format text\|json]` | Show run metadata and optional tail lines. |
| `darklab output <run_id> [--format text\|json]` | Print stored output. |
| `darklab artifacts <run_id>` | List run artifacts. |
| `darklab projects [--limit N] [--offset N] [--format text\|json\|ndjson]` | List projects. |
| `darklab project <project_id> [--format text\|json]` | Show one project. |
| `darklab project-findings <project_id> [--limit N] [--offset N] [--format text\|json\|ndjson]` | List project findings. |
| `darklab project-packages <project_id> [--limit N] [--offset N] [--format text\|json\|ndjson]` | List evidence packages. |
| `darklab download <run_id> --artifact ARTIFACT_ID --out DIR` | Download one artifact. |

`darklab download` requires `--artifact`; without it, use `darklab artifacts <run_id>` first. Downloads use the server's attachment filename only after reducing it to a safe local basename, and the CLI refuses to overwrite an existing file. Workspace ZIP download is not exposed in API v1.

## CLI Configuration

Config precedence is:

1. flags such as `--api-url`, `--token`, and `--timeout`
2. environment variables: `DARKLAB_API_URL`, `DARKLAB_TOKEN`, `DARKLAB_TIMEOUT`
3. `~/.config/darklab/config.toml`
4. defaults

Example config file:

```toml
api_url = "https://shell.example.com"
token = "tok_your_session_token"
timeout = 30
```

`api_url` must include `http://` or `https://`. Local and LAN URLs can use plain HTTP and custom ports, such as `http://192.168.1.3:9999`. The config file is parsed as TOML, so normal TOML quoting, inline comments, and numeric values work as expected.
