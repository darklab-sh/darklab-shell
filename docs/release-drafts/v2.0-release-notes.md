# darklab_shell v2.0 Release Notes

For the full list of changes included in this release, see the v2.0 section in [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- **Projects turn recon work into reusable case workspaces.**
  - Projects can group runs, targets, findings, Atlas entities, artifacts, labels, notes, and evidence packages around a shared active context.
  - The shell, History drawer, Run Details, Projects modal, and mobile sheet flow all understand project links, so adding or removing work from a project stays visible across the app.
  - Remove-from-project confirmations show the disposable entity links, curated entity links, and related findings that will leave the project before anything is unlinked.
  - Large projects stay responsive with paged project lists, runs, findings, entities, and artifacts, scale counts on project rows, prefetched finding-state hints on tab labels, run/target filters across the paged project tabs, and finding filters for command, status, severity, scope, labels, and note state.
  - Active-project capture can link completed external runs, optionally add generated Atlas entities, surface discovered targets for review, and leave clear transcript notices when project capture happens.
  - Project guardrails separate overall links, linked Atlas entities, and discovered/manual project targets so high-volume runs can add large entity sets without exhausting the target-review limit.
  - The terminal `project` command can create, select, rename, clear, archive, link, unlink, and manage active-project targets without opening the modal.
  - Evidence packages export selected project context as static HTML, Markdown, JSON, transcripts, findings, targets, labels, notes, optional raw artifacts for raw packages, and redacted text/JSON artifact derivatives for redacted packages, with bulk selection controls, drift checks, best-guess ZIP and expanded-size estimates, polled archive-preparation feedback, and transcript-only support when Files is disabled.

- **Session Entity Atlas gives extracted entities and findings a first-class triage surface.**
  - Atlas tracks session-scoped hosts, IPs, domains, hashes, CVEs, URLs, deduped findings, source-run links, finding occurrences, project links, labels, notes, and cached intel snapshots, with shared recalculation keeping source-run pointers accurate after cleanup or run deletion.
  - Desktop and mobile Atlas views support paged lists, detail panels, label/note-aware search, searchable source-run filters across Atlas tabs, exports, run-retaining cleanup with curated-row guardrails, visible-page bulk actions, project handoff, and direct launches from History, Run Details, transcript tokens, Projects, and `Alt+A`.
  - Saved Atlas views let repeat triage filters be stored per session and reset from one clear-filters action, while suppression controls hide noisy entities and findings from default Atlas and Projects views without deleting source data.
  - Large sessions are handled with visible-row metadata batching, paged detail collections, stale-request cancellation, and deferred rendering for full provider payloads.

- **External intel and encrypted secrets make provider-backed enrichment safer to use.**
  - App-native intel lookups cover providers such as Shodan, Censys, VirusTotal, GreyNoise, AlienVault OTX, AbuseIPDB, Team Cymru, crt.sh, NVD, URLhaus, ThreatFox, Vulners, urlscan.io, SecurityTrails, RouteViews, and IPinfo.
  - Provider metadata, response normalization, caching, rate limits, quota backoff, audit events, CLI wrappers, and the `intel` terminal command share one provider model.
  - The encrypted secrets vault stores per-session API credentials without exposing values in transcripts, history, route responses, logs, snapshots, or styled exports.
  - Options now separates Preferences from Secrets, shows provider readiness, and keeps API key management in a replace-only browser flow. The terminal `secret` and `config` commands expose the same provider and project-capture settings from the shell.

- **Interactive PTY mode adds a guarded terminal surface for tools that need a real TTY.**
  - Enabled instances can run interactive commands such as `nc --interactive`, `telnet --interactive`, `mtr --interactive`, `ffuf --interactive`, and `masscan --interactive` in a tab-scoped xterm.js modal.
  - PTY runs have command-registry owned settings, bounded per-session concurrency, Redis-capable routing for multi-worker deployments, a single-worker fallback, and reload/Status Monitor reattach through bounded terminal snapshots with stale-age notices.
  - Opening the same live PTY from another browser client cleanly displaces the previous owner tab, and PTY buffer/input/heartbeat/snapshot stream behavior is configurable for busier deployments.
  - Completed PTY runs preserve useful terminal output in saved history while shaping noisy screen redraws into cleaner transcripts.
  - Safety controls cover input profiles, `Ctrl+C` forwarding, input and resize rate limits, client-side input batching, workspace-aware spawn validation, environment allowlisting, stale-state cleanup, `/diag` operator metrics, and clear dependency errors.

- **Long, noisy output stays usable and searchable.**
  - Commands that produce huge output no longer have to render every line live. The tab pauses live rendering after the configured threshold, keeps kill controls available, and records the complete output for later review.
  - Dense live streams keep draining from the server while the browser renders output in small chunks, and live output travels in batches before it reaches Redis/SSE, so noisy commands don't slow down just because the transcript is busy.
  - Completed high-volume runs tell you how much output was skipped in the live tab, while Run Details, permalinks, and exports can still reach the saved transcript.
  - Killing a very noisy run now drops pending browser output instead of letting old buffered lines keep painting after the command is stopped.
  - Structured output powers practical search and triage: History, API, and CLI reads can filter by signal, severity, role, entity, and entity type; Run Details and exports show summaries; dense permalink and HTML exports can toggle finding/entity highlights.
  - Run comparison, watcher diffs, notifications, and evidence packages all understand the same structured output, so entity deltas, output counts, and transcript provenance move with the run instead of living only in the terminal view.
  - Tool boilerplate is quieter. Gobuster startup summaries, ffuf and Masscan banners, Nmap help links, ProjectDiscovery banner links, and registry-declared external help output no longer pollute findings or Atlas entity capture. Nmap, `dig`, `wget --server-response`, Shodan CLI, IPinfo CLI, OpenSSL `s_client`, ffuf, and assetfinder output highlight useful response, DNS, host, ownership, certificate, TLS, discovered-URL, and passive asset metadata, and share/export redaction scrubs matching entity values.

- **Headless API and CLI support automation without bypassing browser guardrails.**
  - `/api/v1` accepts durable session tokens, uses one JSON error shape, applies shared rate limits, and documents its public contract in the checked-in OpenAPI snapshot.
  - Scripts can start runs, follow live streams, cancel jobs, wait for completion, read output ranges, search history, download artifacts, inspect Atlas/project data, and link CLI-started runs back to projects.
  - API-started runs use the same command validation, registry rewrites, workspace handling, active-project capture, Atlas capture, and project-link checks as browser-started runs.
  - The bundled `darklab` CLI wraps the API for runs, history, output grep, artifacts, Atlas, projects, schedules, notifications, downloads, and installable static shell completion, with text tables, TOML config, clean Ctrl+C stream detaches, and safer artifact downloads.

- **AI assists summarize completed runs and draft safer next commands.**
  - Optional AI cards in Run Details can summarize completed external runs and draft follow-up commands without changing the saved transcript, findings, Atlas entities, search text, or comparison input.
  - The feature is disabled by default and built for private OpenAI-compatible providers first, including the bundled llama.cpp Compose profile with persisted Hugging Face model cache and predictable single-slot prompt reuse for CPU-only hosts.
  - AI requests use Redis-backed write limits, enqueue locks, provider-call slots, a dedicated worker, cached completed assists, streamed elapsed/token progress when providers report it, and `/diag` provider checks plus a rate-limited test prompt.
  - Summaries use compact context, deterministic saved-signal merge, redaction-aware target wording, open-port count repair, no-actionable-issue wording, and fallback handling for local model truncation.
  - Next-command drafts get a compact tool and approved-wordlist menu, then are validated before they become copyable: command roots, trusted targets, redaction placeholders, known open ports, missing command targets, app-known SecLists wordlist paths, near-duplicate scanner follow-ups, and known-bad flags are checked outside the model.
  - Accepted suggestions can be copied, and deployments that opt into Run actions still submit them through the normal composer path so command policy remains the final gate. Blocked drafts stay visible with rejection reasons for review.
  - AI storage, audit rows, logging, bounded metrics, provider timing details, API routes, OpenAPI docs, operator configuration, architecture notes, and the AI privacy posture doc ship with the feature.

- **Schedules, watchers, and outbound notifications automate follow-up work.**
  - Outbound notifications can send run and watcher events through generic JSON webhooks, Slack, Discord, Telegram, Pushover, or SMTP email. Channels use vault-backed secrets, test sends report real delivery status, and private-network webhook targets are blocked unless operators explicitly allow them.
  - The Options **Notifications** tab manages durable session-owned channels and shows recent delivery audit rows. API and CLI users get the same channel management, test-send, and audit surfaces.
  - Scheduled commands have durable schedules, fire-audit rows, strict cron/timezone handling, missed-fire recovery, revoked-token and overlap auditing, selected-timezone previews, previous-fire comparison actions, and browser/API/CLI/terminal management paths.
  - Watchers monitor command output against a baseline, optionally use the first run as that baseline, classify meaningful changes, send changed/error/recovered notifications, and show readable fire-audit diffs with direct baseline-vs-fire comparison.
  - The scheduler and notification workers are supervised, deployment-aware, and resilient to Postgres restarts, with clear audit rows and logs when work is skipped, deferred, retried, or dead-lettered.

- **Postgres, storage diagnostics, and metrics make larger deployments easier to operate.**
  - darklab_shell can run on SQLite or Postgres through shared backend and dialect helpers, with Postgres migrations, pool support, lower-latency JIT defaults, optional Compose service wiring, and backend-aware query paths for History, Projects, Files, Atlas, secrets, `/diag`, and `/metrics`.
  - SQLite-to-Postgres cutovers have an offline helper and operator guide for schema setup, isolated-schema testing, batch copying, JSON handling, secret-key confirmation, body-store verification, resume mode, and Compose-network migration runs.
  - `/diag` now includes storage breakdowns for SQLite and Postgres, largest-run hints, object counts, relation/table sizing, shared diagnostics snapshots used by Prometheus, a fast classifier inspector for checking how one output line will be categorized, and an on-demand classifier drift report for sampling recent saved output.
  - The Prometheus `/metrics` endpoint exposes bounded-label operational metrics for HTTP traffic, runs, PTY activity, rate limits, broker health, database latency, workspace health, intel providers, evidence packages, findings, snapshots, client errors, and unhandled exceptions.
  - Structured logs now cover API runs, broker streams, PTY lifecycle, evidence package builds, migrations, secrets, Atlas cleanup/suppression, full-output fallback, and expected degraded states with clearer fields for troubleshooting.
  - `docs/storage-scaling.md` explains measured SQLite growth, body-store thresholds, and when Postgres is the better fit for heavier multi-user deployments.

- **Command, History, Run Details, and mobile workflows are more consistent.**
  - Run Details and mobile History expose the same saved-run actions, including copy, restore, compare, permalink, delete, metadata editing, project link/unlink, add-to-active-project, copy run id, Atlas source-run handoff, and run-scoped Atlas entity browsing.
  - History supports visible-page bulk project and delete actions, project-aware filtering, full-session terminal history output, Atlas entity/finding count lines for external runs, clearer built-in/external run handling, and safer project-link actions for already linked runs.
  - Recent target autocomplete understands domains, IPs, URLs, port sets, case-sensitive flags, host/IP command slots, and file-list inputs more cleanly.
  - Select dropdowns, output controls, pagination rows, modal tabs, panel tabs, entity rows, Atlas actions, Projects actions, and mobile action sheets now share the same app primitives, while backend parity checks keep the SQLite and Postgres schema definitions aligned.
  - The Status Monitor's Command Constellation defaults to your active hours so the canvas stays a full sky; toggle to **Full day** in the legend for strict 24-hour reading. Edges with no activity are trimmed, and interior low-density bands (a sleep window when active hours stretch across both ends of the day) collapse onto a `//` seam marker so the visible canvas reads as continuous clock time. Empty patches are filled by a desaturated ambient layer, and a clock-pinned daylight gradient paints the 24h cycle behind the stars so noon, dusk, and night sit at their true hour-of-day positions in either mode. Stars also use structured output metadata, with stronger tones for warning/error runs and larger points when a run produced more findings.

- **Guidance, demos, and release assets are ready for the bigger v2.0 surface.**
  - The FAQ, app hints, and onboarding tour introduce Projects, Atlas, the `project` command, Run Comparison, and interactive PTY mode in user-facing language.
  - Demo and screenshot capture packs cover Projects, Atlas, Run Comparison, and the desktop PTY modal with deterministic sample data for release assets.
  - Python linting now runs through Ruff in local scripts, CI, and the tracked pre-commit hook.
