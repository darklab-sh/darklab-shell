# darklab_shell v2.0 Release Notes

For the full list of changes included in this release, see the v2.0 section in [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- **Projects turn recon work into reusable case workspaces.**
  - Projects can group runs, targets, findings, Atlas entities, artifacts, labels, notes, and evidence packages around a shared active context.
  - The shell, History drawer, Run Details, Projects modal, and mobile sheet flow all understand project links, so adding or removing work from a project stays visible across the app.
  - Remove-from-project confirmations show the disposable entity links, curated entity links, and related findings that will leave the project before anything is unlinked.
  - Large projects stay responsive with paged project lists, runs, findings, entities, and artifacts, scale counts on project rows, prefetched finding-state hints on tab labels, run/target filters across the paged project tabs, and finding filters for command, status, severity, scope, labels, and note state.
  - Active-project capture can link completed external runs, optionally add generated Atlas entities, surface discovered targets for review, and leave clear transcript notices when project capture happens.
  - The terminal `project` command can create, select, rename, clear, archive, link, unlink, and manage active-project targets without opening the modal.
  - Evidence packages export selected project context as static HTML, Markdown, JSON, transcripts, findings, targets, labels, notes, and optional artifacts, with redaction modes, drift checks, size estimates, and transcript-only support when Files is disabled.

- **Session Entity Atlas gives extracted entities and findings a first-class triage surface.**
  - Atlas tracks session-scoped hosts, IPs, domains, hashes, CVEs, URLs, deduped findings, source-run links, finding occurrences, project links, labels, notes, and cached intel snapshots.
  - Desktop and mobile Atlas views support paged lists, detail panels, label/note-aware search, searchable source-run filters across Atlas tabs, exports, run-retaining cleanup with curated-row guardrails, visible-page bulk actions, project handoff, and direct launches from History, Run Details, transcript tokens, Projects, and `Alt+A`.
  - Saved Atlas views let repeat triage filters be stored per session and reset from one clear-filters action, while suppression controls hide noisy entities and findings from default Atlas and Projects views without deleting source data.
  - Large sessions are handled with visible-row metadata batching, paged detail collections, stale-request cancellation, and deferred rendering for full provider payloads.

- **External intel and encrypted secrets make provider-backed enrichment safer to use.**
  - App-native intel lookups cover providers such as Shodan, Censys, VirusTotal, GreyNoise, AlienVault OTX, AbuseIPDB, Team Cymru, crt.sh, NVD, URLhaus, ThreatFox, Vulners, urlscan.io, SecurityTrails, RouteViews, and IPinfo.
  - Provider metadata, response normalization, caching, rate limits, quota backoff, audit events, CLI wrappers, and the `intel` terminal command share one provider model.
  - The encrypted secrets vault stores per-session API credentials without exposing values in transcripts, history, route responses, logs, snapshots, or styled exports.
  - Options now separates Preferences from Secrets, shows provider readiness, and keeps API key management in a replace-only browser flow. The terminal `secret` and `config` commands expose the same provider and project-capture settings from the shell.

- **Interactive PTY mode adds a guarded terminal surface for tools that need a real TTY.**
  - Enabled instances can run interactive commands such as `nc --interactive`, `telnet --interactive`, `mtr --interactive`, `ffuf --interactive`, and `masscan --interactive` in a tab-scoped xterm.js modal.
  - PTY runs have command-registry owned settings, bounded per-session concurrency, Redis-capable routing for multi-worker deployments, a single-worker fallback, and reload/Status Monitor reattach through bounded terminal snapshots.
  - Completed PTY runs preserve useful terminal output in saved history while shaping noisy screen redraws into cleaner transcripts.
  - Safety controls cover input profiles, `Ctrl+C` forwarding, input and resize rate limits, client-side input batching, workspace-aware spawn validation, environment allowlisting, stale-state cleanup, and clear dependency errors.

- **High-volume output handling keeps noisy commands usable.**
  - Brokered output pauses per-line live rendering after the configured threshold, shows status rows while the run is active, and keeps kill controls, raw previews, metadata, saved previews, and full-output artifacts intact.
  - Resume-live-rendering is available only while a command is still running, and completed high-volume runs print a final summary that tells users how many lines were not rendered live in the tab.
  - Large saved previews are byte-bounded, and tool-created state now lives under `/tools` so scanner config, resume folders, and managed databases stay out of the main workspace root.

- **Postgres, storage diagnostics, and metrics make larger deployments easier to operate.**
  - darklab_shell can run on SQLite or Postgres through shared backend and dialect helpers, with Postgres migrations, pool support, lower-latency JIT defaults, optional Compose service wiring, and backend-aware query paths for History, Projects, Files, Atlas, secrets, `/diag`, and `/metrics`.
  - SQLite-to-Postgres cutovers have an offline helper and operator guide for schema setup, batch copying, JSON handling, secret-key confirmation, body-store verification, resume mode, and Compose-network migration runs.
  - `/diag` now includes storage breakdowns for SQLite and Postgres, largest-run hints, object counts, relation/table sizing, and shared diagnostics snapshots used by Prometheus.
  - The Prometheus `/metrics` endpoint exposes bounded-label operational metrics for HTTP traffic, runs, PTY activity, rate limits, broker health, database latency, workspace health, intel providers, evidence packages, findings, snapshots, client errors, and unhandled exceptions.
  - `docs/storage-scaling.md` explains measured SQLite growth, body-store thresholds, and when Postgres is the better fit for heavier multi-user deployments.

- **Command, History, Run Details, and mobile workflows are more consistent.**
  - Run Details and mobile History expose the same saved-run actions, including copy, restore, compare, permalink, delete, metadata editing, project link/unlink, add-to-active-project, copy run id, Atlas source-run handoff, and run-scoped Atlas entity browsing.
  - History supports visible-page bulk project and delete actions, project-aware filtering, full-session terminal history output, Atlas entity/finding count lines for external runs, clearer built-in/external run handling, and safer project-link actions for already linked runs.
  - Recent target autocomplete understands domains, IPs, URLs, port sets, case-sensitive flags, host/IP command slots, and file-list inputs more cleanly.
  - Select dropdowns, output controls, pagination rows, modal tabs, panel tabs, Atlas actions, Projects actions, and mobile action sheets now share the same app primitives.

- **Guidance, demos, and code organization are ready for the bigger v2.0 surface.**
  - The FAQ, app hints, and onboarding tour introduce Projects, Atlas, the `project` command, Run Comparison, and interactive PTY mode in user-facing language.
  - Demo and screenshot capture packs cover Projects, Atlas, Run Comparison, and the desktop PTY modal with deterministic sample data for release assets.
  - Backend services now live under focused `app/core/` and `app/services/` modules, while browser code for major features has moved out of broad shared files into feature-owned modules.
  - Python linting now runs through Ruff in local scripts, CI, and the tracked pre-commit hook.
