# darklab_shell v2.0 Release Notes

For the full list of changes included in this release, see the v2.0 section in [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- Project workspace adds a case-style grouping layer for projects, runs, run-owned workspace artifacts, targets, findings, labels, notes, and packages.
  - The shell chrome now shows active project context with a clickable HUD chip, automatic eligible external-run linking, optional Atlas entity capture for those linked runs, active-project capture controls, transcript notices, cross-tab refresh, and project-aware History filtering.
  - Shell-first `project` commands cover create/use/archive/unarchive/delete, target management, quick-add target inference, nested autocomplete, tab-aware Link last run backfill, and linked run management.
  - The Projects modal supports current/archived grouping, desktop/mobile pagination for large project lists, deletion, project labels and notes, editable targets, linked Atlas entities, linked runs, findings, artifacts, and packages. It loads lightweight counts for the visible project rows, hydrates the full summary only for the selected project, pages linked runs, pages the Findings tab with server-side totals in an ungrouped list that shows each row's source command, uses matching top and bottom pagination rows across paged Runs, Findings, Entities, and Artifacts tabs, shows in-flight page status while switching pages, keeps bottom pagers anchored at the bottom when result height changes, relies on run/status/target, command-root, severity, scope, label, and note-state filters for narrowing, supports visible-page Project Findings bulk review, uses indexed per-row occurrence lookups instead of whole-table occurrence ranking during Findings page loads, and fetches Project Entities and Artifacts from bounded endpoints instead of carrying every row in the summary. Run rows keep finding/artifact chips tied to server-side per-run counts, run-link confirmations can also include the Atlas entities found in the source run, with the count shown before saving, auto-linked active-project runs can add their Atlas entities after entity materialization, and run-unlink confirmations can remove same-run, non-curated Atlas entity links from the project. Run, finding, Atlas entity, artifact, workspace-file, and package rows expose label/note metadata editing from real UI flows, and the empty state hides project-only label/note editors until a project exists.
  - Project tabs stay anchored while tab-specific filters render underneath them, so Runs, Findings, Artifacts, and unfiltered tabs switch without moving the tab row.
  - Modal and panel tabs now share one tab-strip primitive, keeping Run Details, Atlas, Projects, Project entity-type tabs, and Options aligned on active, hover, focus, and overflow behavior.
  - Project Entities mirrors Atlas's Hosts/IPs, Domains, Hashes, CVEs, and URLs tabs for project-linked entities. It pages each entity type on desktop and mobile, can add session Atlas entities from a picker, show cached intel provider context, open entities in Atlas for deeper intel review or refresh, bulk-unlink project entity links, and export project-scoped entities as CSV or JSONL.
  - Atlas can save named views for repeat triage filters, and can suppress noisy entities and findings without deleting source data. Suppressed rows are hidden from default Atlas and Projects views, can be reviewed through the suppressed filter, restored from desktop or mobile, and stay available in filtered exports.
  - On mobile, Projects opens as a sheet-native list/detail flow with count-chip drill-in, tabbed project sections, row action sheets, retryable load errors, package-wizard sheet handling, and app-native pressable, row, and scrollbar primitives.
  - Findings and targets now support active-project autocomplete, auto-discovered pending targets with Confirm/Dismiss controls, persisted multi-target associations, run-scoped finding capture/review, source-run restore with line highlighting, review state updates, filters, sorting, and artifact preview/download status. Artifact rows render in pages on desktop and mobile so large captured-file sets stay manageable.
  - Evidence packages provide a guided export flow with package labels/notes, explicit entity selection, transcript/finding/artifact/target selection, artifact inclusion, private-note inclusion, redaction mode, pre-build size estimates, same-selection re-export, drift/skipped-item reporting, and temp-file-backed downloads.
  - Instances with Files disabled can still use project CRUD, run links, targets, findings, labels/notes, comparisons, and transcript-only evidence packages. File-backed artifact actions become explicitly unavailable, and the Projects modal hides the Artifacts tab plus artifact jump chips instead of showing stale or missing file rows.
  - Run comparison now uses one hunk-based viewer for History and Projects flows, with folded equal context, lazy equal-line expansion, side-by-side/unified/changes-only/findings-only views, order-insensitive finding/artifact object comparison, and baseline-label support through the canonical `/history/compare` API.
  - Run Details and mobile History now expose the richer saved-run workflow consistently: row taps open details, Copy command and Restore stay primary on mobile, and secondary actions such as compare, permalink, delete, metadata editing, project linking, add-to-active-project, and copy run id live in app-native overflow menus.
  - Package archives include `manifest.json`, `README.md`, static `index.html`, selected run transcript pages, full-text companions for capped transcripts, finding/target JSON and Markdown exports, selected label/private-note exports, project/entity/target note Markdown exports, optional raw artifacts, and redacted variants.
  - Project finding capture now stores plain-text findings even when scanner output includes ANSI color formatting, target auto-discovery avoids re-announcing targets that were already known or dismissed, and Atlas entity extraction ignores file-like names inside URL paths while still capturing the real URL host.
- Operator and developer support for project workspace includes the database relationship model, project summary aggregation, run-scoped artifact/finding/label/note metadata in history, restored-run JSON, workspace file listings with labels/notes, permalink views, `/diag` object counts and storage breakdowns for SQLite/Postgres, a measured storage-scaling guide, configurable body-store offload thresholds for large run search text, snapshot bodies, and Atlas intel payloads, IP-gated Prometheus `/metrics` for Grafana/Prometheus monitoring, configurable project workspace quotas, shared write-route limits, async-safe app-native select option refresh, an Atlas onboarding tour chapter, and bounded compare APIs for hunk output plus lazy equal-region paging.
- High-volume brokered output now protects the browser by pausing per-line live rendering after `high_volume_output_line_threshold` received lines, showing periodic status rows, and offering a resume-live-rendering action for new output while the run is active. Once the command exits or is killed, the stale resume action is disabled; normal preview and full-output storage settings stay unchanged.
- Normal command stream recovery now reuses the original browser tab when the tab still exists, keeps the timer anchored to the server start time, and prints clear reattach notices after reload or stream-detach recovery.
- Interactive PTY mode adds a real terminal surface for interactive tools such as `nc --interactive`, `telnet --interactive`, `mtr --interactive`, `ffuf --interactive`, and `masscan --interactive`, backed by registry-owned settings, dedicated PTY routes, Redis-friendly control routing, and a single-worker local fallback.
- The live PTY surface uses a tab-scoped xterm.js modal with fit-addon support, startup asset preloading, asset-load retry handling, theme refresh, reusable tab overlays, hidden-tab resize suppression, desktop-only mobile guardrails, and the same close/kill confirmation flow used by normal running tabs.
- PTY runs support bounded concurrency per browser session, defaulting to four active PTYs, while keeping each live terminal scoped to the tab that started it.
- Reload recovery and Status Monitor Attach restore active PTY runs from bounded ANSI terminal snapshots, preserving colors, text attributes, cursor position, and the latest visible screen when server-side terminal capture is available. Redis-backed deployments publish distributed, rate-capped snapshots so any worker can serve reattach without sticky routing.
- Completed PTY runs preserve live terminal formatting in the modal while appending a saved static transcript and exit status to the parent tab. The command registry controls transcript shaping, so `mtr` saves the final visible frame while `ffuf` and `masscan` save scrolled findings without common transient progress/status redraw lines.
- Interactive PTY mode ships with safety guardrails: explicit `input_safety` profiles, native `Ctrl+C` forwarding, dedicated configurable input rate limits, client-side burst batching for typed input, rate-limited resize requests, UTF-8 byte-aware input trimming, workspace-CWD-aware validation before spawn, a vetted command environment, clear server-side terminal capture dependency errors, stale state cleanup, and actionable snapshot failure statuses.
- The FAQ and app hints now introduce Projects, the `project` shell command, and interactive PTY mode in end-user language. PTY hints and FAQ content stay hidden unless the instance enables interactive PTY.
- The FAQ modal now groups answers under section headers, keeps the whole FAQ searchable in one scroll, and supports direct links to a specific answer or section.
