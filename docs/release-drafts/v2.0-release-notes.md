# darklab_shell v2.0 Release Notes

For the full list of changes included in this release, see the v2.0 section in [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- Project workspace adds a case-style grouping layer for projects, runs, run-owned workspace artifacts, targets, findings, labels, notes, and packages.
  - The shell chrome now shows active project context with a clickable HUD chip, automatic eligible external-run linking, active-project capture controls, transcript notices, cross-tab refresh, and project-aware History filtering.
  - Shell-first `project` commands cover create/use/archive/unarchive/delete, target management, quick-add target inference, nested autocomplete, tab-aware Link last run backfill, and linked run management.
  - The Projects modal supports current/archived grouping, deletion, project labels and notes, editable targets, linked Atlas entities, linked runs, findings, artifacts, and packages. Run-link confirmations can also include the Atlas entities found in the source run, with the count shown before saving, and run-unlink confirmations can remove same-run, non-curated Atlas entity links from the project. Run, finding, Atlas entity, artifact, workspace-file, and package rows expose label/note metadata editing from real UI flows, and the empty state hides project-only label/note editors until a project exists.
  - Project tabs stay anchored while tab-specific filters render underneath them, so Runs, Findings, Artifacts, and unfiltered tabs switch without moving the tab row.
  - Modal and panel tabs now share one tab-strip primitive, keeping Run Details, Atlas, Projects, Project entity-type tabs, and Options aligned on active, hover, focus, and overflow behavior.
  - Project Entities mirrors Atlas's Hosts/IPs, Domains, Hashes, CVEs, and URLs tabs for project-linked entities. It can add session Atlas entities from a picker, show cached intel provider context, open entities in Atlas for deeper intel review or refresh, bulk-unlink project entity links, and export project-scoped entities as CSV or JSONL.
  - On mobile, Projects opens as a sheet-native list/detail flow with count-chip drill-in, tabbed project sections, row action sheets, retryable load errors, package-wizard sheet handling, and app-native pressable, row, and scrollbar primitives.
  - Findings and targets now support active-project autocomplete, auto-discovered pending targets with Confirm/Dismiss controls, persisted multi-target associations, run-scoped finding capture/review, source-run restore with line highlighting, review state updates, filters, sorting, and artifact preview/download status.
  - Evidence packages provide a guided export flow with package labels/notes, explicit entity selection, transcript/finding/artifact/target selection, artifact inclusion, private-note inclusion, redaction mode, pre-build size estimates, same-selection re-export, drift/skipped-item reporting, and temp-file-backed downloads.
  - Instances with Files disabled can still use project CRUD, run links, targets, findings, labels/notes, comparisons, and transcript-only evidence packages. File-backed artifact actions become explicitly unavailable, and the Projects modal hides the Artifacts tab plus artifact jump chips instead of showing stale or missing file rows.
  - Run comparison now uses one hunk-based viewer for History and Projects flows, with folded equal context, lazy equal-line expansion, side-by-side/unified/changes-only/findings-only views, order-insensitive finding/artifact object comparison, and baseline-label support through the canonical `/history/compare` API.
  - Run Details and mobile History now expose the richer saved-run workflow consistently: row taps open details, Copy command and Restore stay primary on mobile, and secondary actions such as compare, permalink, delete, metadata editing, project linking, add-to-active-project, and copy run id live in app-native overflow menus.
  - Package archives include `manifest.json`, `README.md`, static `index.html`, selected run transcript pages, full-text companions for capped transcripts, finding/target JSON and Markdown exports, selected label/private-note exports, project/entity/target note Markdown exports, optional raw artifacts, and redacted variants.
  - Project finding capture now stores plain-text findings even when scanner output includes ANSI color formatting, target auto-discovery avoids re-announcing targets that were already known or dismissed, and Atlas entity extraction ignores file-like names inside URL paths while still capturing the real URL host.
- Operator and developer support for project workspace includes the database relationship model, project summary aggregation, run-scoped artifact/finding/label/note metadata in history, restored-run JSON, workspace file listings with labels/notes, permalink views, `/diag` object counts and SQLite storage breakdowns, IP-gated Prometheus `/metrics` for Grafana/Prometheus monitoring, configurable project workspace quotas, shared write-route limits, async-safe app-native select option refresh, an Atlas onboarding tour chapter, and bounded compare APIs for hunk output plus lazy equal-region paging.
- Interactive PTY mode adds a real terminal surface for interactive tools such as `nc --interactive`, `telnet --interactive`, `mtr --interactive`, `ffuf --interactive`, and `masscan --interactive`, backed by registry-owned settings, dedicated PTY routes, Redis-friendly control routing, and a single-worker local fallback.
- The live PTY surface uses a tab-scoped xterm.js modal with fit-addon support, startup asset preloading, asset-load retry handling, theme refresh, reusable tab overlays, hidden-tab resize suppression, desktop-only mobile guardrails, and the same close/kill confirmation flow used by normal running tabs.
- PTY runs support bounded concurrency per browser session, defaulting to four active PTYs, while keeping each live terminal scoped to the tab that started it.
- Reload recovery and Status Monitor Attach restore active PTY runs from bounded ANSI terminal snapshots, preserving colors, text attributes, cursor position, and the latest visible screen when server-side terminal capture is available. Redis-backed deployments publish distributed, rate-capped snapshots so any worker can serve reattach without sticky routing.
- Completed PTY runs preserve live terminal formatting in the modal while appending a saved static transcript and exit status to the parent tab. The command registry controls transcript shaping, so `mtr` saves the final visible frame while `ffuf` and `masscan` save scrolled findings without common transient progress/status redraw lines.
- Interactive PTY mode ships with safety guardrails: explicit `input_safety` profiles, native `Ctrl+C` forwarding, dedicated configurable input rate limits, client-side burst batching for typed input, rate-limited resize requests, UTF-8 byte-aware input trimming, workspace-CWD-aware validation before spawn, a vetted command environment, clear server-side terminal capture dependency errors, stale state cleanup, and actionable snapshot failure statuses.
- The FAQ and app hints now introduce Projects, the `project` shell command, and interactive PTY mode in end-user language. PTY hints and FAQ content stay hidden unless the instance enables interactive PTY.
- The FAQ modal now groups answers under section headers, keeps the whole FAQ searchable in one scroll, and supports direct links to a specific answer or section.
- The onboarding tour introduces the app in short, clickable steps. The terminal `tour` command types each chapter, pauses between chapters, and opens sample commands in a new tab so the tour stays intact while users experiment. The visual tour's Running Commands, History, and Run Comparison previews now match the real terminal output, history drawer rows, and compare modal layout more closely. The modal keeps one stable height while moving through the carousel, FAQ closes when it hands off to the visual tour, and `Try this` actions close the tour before opening the matching app surface.

- Python linting now uses Ruff through `.tooling/ruff.toml`, `npm run lint:py`, GitLab CI, and the tracked pre-commit hook.
- The demo and screenshot capture packs now include Projects, Atlas, Run Comparison, and the desktop interactive PTY modal, so release screenshots and demos cover the major v2.0 surfaces with stable sample data. Mobile capture follows the current full History panel, and the theme-picker browse in the demo is shorter while still feeling like a person scanning down and back up.
- The Command Registry modal now shows subcommand-specific details, including subcommand descriptions, examples, arguments, flags, value hints, workspace file flags, and app-handling notes.
- New feature: Encrypted secrets vault adds normalized `requires_secrets` command metadata, metadata-only secret routes, encrypted per-session storage, app-owned key-file bootstrap with permission repair, session migration support, registry-driven subprocess environment injection, an Options Secrets panel for registry-suggested replace-only add/edit/delete flows, and the `secret` terminal command family without exposing stored values in route responses, transcripts, command text, or logs. Secret routes and command injection require a valid session, duplicate consumer-env bindings are rejected, scanner-user sudo launches preserve only declared secret env names, and runtime command rewrites do not hide the original command root's secret declarations. `secret set NAME` opens the browser value prompt instead of accepting the value in command text; accidentally typed values are scrubbed before transcript/history persistence, migration collisions preserve source secrets, `secret show-consumers` shows app-native and CLI-backed intel provider readiness, custom names remain available for local registry overlays, and interactive PTY registry entries cannot declare `requires_secrets` until that path supports env injection.
- Options now separates Preferences from Secrets: display, identity, run, and compare controls stay in the Preferences tab, while Provider Status, add/refresh actions, and saved API keys live in a dedicated Secrets tab that remembers the last selected tab per session.
- Select dropdowns now follow the shared app-native formatting path, including dynamically rendered confirmation-modal controls such as the encrypted secret picker and Atlas finding review-state picker, plus any `.form-select` inserted after startup. Long option lists stay on-screen with internal scrolling, dialog/modal/sheet menus escape clipped containers, and mobile confirmations focus the themed select trigger instead of opening the browser picker on mount.
- Mobile Atlas now supports filter disclosure controls, orphan-only chips, sticky bulk select mode, shared bottom action sheets, row long-press actions, detail overflow actions, and detail-first launches from entity links. The old collapsed-desktop mobile fallback has been removed, the flow has focused Vitest and Playwright coverage, and Projects uses the same shared action-sheet primitive for its mobile row/action menus.
- New feature: External intel integrations are in place for Shodan, Censys, VirusTotal, GreyNoise, AlienVault OTX, AbuseIPDB, Team Cymru, crt.sh, HIBP Pwned Passwords, NVD, URLhaus, ThreatFox, Vulners, urlscan.io, SecurityTrails, RouteViews, and IPinfo, covering a shared provider metadata registry, canonical entity keys, normalized provider response shapes, normalized-response cache TTLs, per-session provider token buckets, provider quota backoff, redacted lookup audit events, allowlisted `shodan`, `vt`, `greynoise`, `ipinfo`, `urlscan-cli`, and `chaos` CLI wrappers, the app-native `intel ip|domain|url|hash|cve` built-in, per-line output entity metadata for public IPs, hostnames, URLs, hashes, and CVEs, provider secret consumers in Options, `secret show-consumers`, and the `providers` alias, an Options Provider Status modal for usable/missing-key provider state with clickable secret-name setup links, and raw-only intel omission for share/styled export surfaces. - `/diag` now includes a Storage breakdown panel that groups SQLite tables, indexes, and FTS shadow tables by operator area, reports logical payload estimates and largest saved runs, shows allocated/page-level metrics when SQLite has `dbstat`, and falls back cleanly with a scoped banner when `dbstat` is unavailable.
- `/metrics` now exposes Prometheus text for allowlisted operators, covering HTTP traffic, run and PTY lifecycle, rate limits, broker mode and activity, selected DB hot-path latency, DB/Redis/workspace health, intel provider outcomes and cache size, evidence package builds, Atlas/finding counts, snapshots, client errors, and unhandled exceptions. Metric definitions include explicit label-cardinality policies, unknown intel providers collapse to `unknown`, the Gunicorn config marks dead worker metric shards for cleanup so live gauges do not linger after worker exits, and the release also includes a starter Grafana dashboard.
- Tool-created Files state now lives under `/tools`, so ProjectDiscovery config/resume folders and the managed Amass database are grouped away from user-created files at the session workspace root.
- SQLite run previews are now byte-bounded with `output_preview_max_mb`, preventing huge single-line scanner output from bloating the history database while preserving larger output in full-output artifacts when enabled.
- Startup history queries now use targeted SQLite indexes so large history databases do not delay the Recent and Workflows rail menus.
- History restore now distinguishes runs by run identity, so restoring a command no longer jumps to an unrelated existing tab with the same command text.
- Terminal color output is now isolated per tab, so a command that leaves ANSI color state open cannot tint later output in another tab or after a transcript restore.
- Running tabs keep app shortcuts available from the prompt, so users can open UI surfaces, create or switch tabs, copy/permalink/clear output, and still use `Ctrl+C` for kill confirmation while command-entry and editing shortcuts stay blocked.
- The command composer now blocks macOS double-space period substitution from changing terminal input.
- Recent target autocomplete now saves domains, IPs, URLs, and port sets under the active session token, caps each kind separately, and strips URL query strings/fragments before saving.
- Host/IP command slots such as `ping`, traceroute-style tools, `nc`, `telnet`, `mtr`, `whois`, TLS scanners, `naabu`, and `rustscan` now offer recent IPs as well as recent domains without suggesting URL-only targets.
- Recent target capture now skips file-list inputs, so filenames like `subs.txt` are not saved as reusable targets after commands such as `nuclei -l subs.txt`.
- Autocomplete now keeps case-sensitive flags distinct, so `dnsrecon` shows both `-d` and `-D`, `dnsrecon -d` offers compatible recent targets, `dnsrecon -D` offers wordlists, and output filenames are no longer captured as recent targets for that command.
- History row and Run Details project actions now reflect the run's current project links, offering **remove from project** when a run is already linked instead of showing duplicate add actions, and the menu refreshes immediately after link changes. Remove confirmations can also unlink same-run, non-curated Atlas entities from the project.
- Saved runs now keep a built-in/external `run_kind` in history. Fresh databases create it directly, existing databases add and backfill it during startup migration, and built-in rows stay restorable and searchable without showing project-link actions, allowing manual or bulk project links, or feeding project finding capture.
- History select mode supports visible-page bulk actions for completed runs and saved snapshots, including project add/remove for runs and delete for selected history items. The select controls sit below the filters, keep the selected count beside the toggle, and keep the Actions dropdown inside the drawer. On mobile, the hamburger History item and Recent peek both open the full History panel, with search, filters, and bulk actions tucked behind a collapsible `history tools` row, while preserving the current shared type filter instead of reopening as run-only. Bulk remove confirms once, then unlinks selected runs from every project they are linked to instead of asking for one project at a time. Confirming, cancelling, using add-to-active-project, or removing a project link no longer closes the drawer unless the action itself navigates away. Browser coverage now checks checkbox selection, disabled unfinished runs, snapshot deletion, row-action propagation, in-flight locking, project picker flows, mixed select-all state, clear selection, rejection-reason feedback, reset-on-close behavior, desktop bulk add/remove/delete, and mobile toolbar wrapping plus row-body tap selection.
- The terminal `history` command now prints the full session command history instead of using the recent-command cache limit. Prompt Up/Down history, desktop rail recents, and the mobile recent peek still stay capped by `recent_commands_limit`.
- History bulk actions reject incomplete runs, hide cross-session run existence behind normal `not found` results, and reject malformed bulk IDs before querying or logging them.
- History bulk selection changes now repaint from the visible page instead of refetching History, Select All can toggle back to zero selected, and bulk project linking serializes the link-budget check before inserts.
- The source-built OpenSSL in the container now installs its libraries into the platform multiarch path, so the bundled `openssl` command loads the matching OpenSSL libraries on arm64 and amd64.
- Fast-exiting commands no longer show a false "Run not found" stream error while the server is still finalizing the completed run.
- `scripts/container_smoke_test.sh --build` now forces a rebuild of the stable smoke cache image before running the smoke corpus.
- Container smoke tests now reach Docker-published ports correctly from GitLab Docker runners and fail loudly when setup breaks instead of reporting a mostly skipped smoke run.
