# v2.0 Release Merge Request

## Summary

- Adds the project workspace backend foundation: relationship tables, entity/link-source validation, supporting indexes, initial project CRUD/link routes, shell-first `project` commands, a compact Projects modal with target management, current/archived project grouping, project deletion, shared target/run/status filters, sorting, run-row finding/artifact navigation, Link last run backfill, persisted many-to-many finding target associations, auto-discovered project targets from typed command inputs and explicit target-list files, inline finding review, finding source navigation, active-project external-run capture controls with transcript notices and cross-tab modal refresh, active project context, active project shell chrome, History drawer project filtering, automatic external saved-run/snapshot linking, run-scoped artifact capture, capped draft evidence package archives with package row download/re-package/delete/manifest-preview actions and row-level package summaries, a package wizard that emits `manifest.json`, `README.md`, `index.html`, selected run transcript pages with run-grouped transcript/finding/artifact selection and selectable/collapsible run groups, full text companions for capped transcripts, selected finding JSON/Markdown exports with inline metadata, selected target JSON/Markdown exports with inline metadata, selected label/annotation metadata exports, project/annotation/target note Markdown exports, linked package export sections, selected artifacts for raw packages, pre-build package size estimates, a versioned CSS/font snapshot for offline package pages, redacted metadata/transcript output for redacted packages, skipped-item metadata with pre-build drift preview, same-selection package re-export, temp-file-backed package downloads, and session migration support for future project, artifact, target, finding, label, annotation, package, and active-project preference flows.
- Adds first-pass interactive PTY support for screen-oriented tools as a cohesive, guarded feature: configured commands run in a tab-scoped xterm.js modal, route through dedicated Redis-capable PTY endpoints, and persist completed output as normal saved history/search/finding content.
- Ships PTY with first-pass safeguards for registry-owned command settings, bounded concurrency, input policy, reattach snapshots, transcript shaping, route rate limits, stale-state cleanup, and multi-worker operation.
- Adds database preview-size protection, startup query indexes, and two terminal/history polish fixes found during v2.0 work.

- App-owned project entity/link-source constants plus bootstrap/index tests so project routes share one relationship vocabulary.

- Terminal `project` commands for listing, creating, selecting, clearing, archiving, linking, and unlinking project workspace records.
- Terminal `project target` commands for listing, adding, quick-adding, and removing active-project targets.

- Project finding rows show associated project targets when a persisted finding matched one.

- Project finding rows expose inline review-state controls backed by the persisted finding review API.
- Project finding rows restore their source run and highlight the persisted finding line number in the terminal transcript.
- Active-project target autocomplete for matching domain, host, IP, CIDR, URL, and generic target slots.
- Project summary API that aggregates linked runs, snapshots, workspace files, targets, run artifact details, artifact availability/checksum status, and run-derived finding/metadata counts without directly linking derived records.
- Project target CRUD routes for domains, URLs, hosts, IPs, CIDRs, and named port sets.
- Backend quick-add target inference for selected text or explicit values, preserving full IP addresses while detecting URLs, CIDRs, IPs, and domains.
- Auto-discovered project targets from typed command inputs and explicit target-list file flags, with pending target rows that can be confirmed or dismissed without blocking later manual re-adds.
- Draft evidence package routes that snapshot project links, targets, counts, package redaction mode, artifact-inclusion preference, selected transcript run ids, pre-build archive size estimates, Markdown summaries with project notes, static index/permalink-context-backed run transcript HTML with package export navigation, versioned CSS/font snapshotting, offline finding sorting, and inline finding metadata, text companions for capped transcripts, finding JSON/Markdown exports, target JSON/Markdown exports, selected label/private-annotation metadata exports, note Markdown exports, artifact size/hash drift checks, pre-build skipped/drift preview, skipped-item reporting, selected raw artifacts for raw packages, and redacted manifest/HTML/Markdown/finding/target/metadata/notes/transcript output for redacted packages into a capped downloadable archive.
- First-pass project workspace guardrails covering shared write-route rate limits, per-session/project quotas for persisted project records, and evidence package archive size/artifact-count caps.
- Project-linked workflow promotion that turns selected linked run commands into a saved user workflow, reports automatic truncation metadata, and binds a matching project target as `{{target}}` only when the target choice is unambiguous or explicit.
- Run-to-run project comparison for finding and workspace artifact additions/removals.
- Run-label baseline selection for project comparisons.
- Entity-scoped label and annotation routes that work for supported records outside projects, so projects can aggregate them later instead of owning them.
- Active project context display in desktop and mobile shell chrome without changing command-entry behavior.
- The active project HUD chip opens the Projects modal, giving the active context a direct navigation path.
- Automatic project links for completed server-owned runs, browser-owned built-ins, and snapshots created from project-associated tabs.
- Declared workspace file flag artifact capture for completed real-command runs, with artifact metadata exposed through history, run permalink JSON, and run permalink HTML metadata.
- Run-scoped finding rows are captured from server-side output signal metadata for completed runs, regardless of active project context.
- Persisted findings attach to every matching project target when the finding text contains linked project target values.
- Run-scoped finding list/review routes let persisted findings move through `new`, `reviewed`, `important`, `false_positive`, and `needs_followup` without requiring a project view.
- Projects modal filters are shared across project views, with target, run, and finding review-state filters surfaced as labeled chips; run rows show per-run finding/artifact counts and use those filters to jump into focused Findings or Artifacts views while keeping Restore explicit.
- Project artifact rows expose availability badges plus scoped preview/download actions for still-available workspace artifacts.
- History and run permalink payloads expose artifact, finding, label, and annotation counts for source runs.
- Restored history JSON includes same-session finding, label, and annotation details for source runs.
- Workspace file listings include lightweight artifact, run, and project metadata for files captured from command input/output flags.
- `/diag` reports project workspace object counts for projects, artifacts, findings, annotations, and future packages.

## Changed

- Run previews stored in SQLite are capped by `output_preview_max_mb` in addition to existing line limits.
- Recent-command, snapshot, and workflow startup queries use targeted session-aware SQLite indexes.
- Recent domain capture now preserves complete IPv4 addresses from domain-style argument slots while rejecting partial numeric hosts.
- Redacted evidence packages apply the existing share/export redaction rules to manifests, HTML, Markdown, run transcript pages, and package filenames. Raw artifact files are excluded from redacted packages until artifact-content redaction is available.

## Fixed

- Restoring a history run now reuses a tab only when the run identity matches, not merely when the command text matches.
- macOS double-space period substitution is normalized out of the command composer before it updates autocomplete or draft state.

## Validation

- Focused validation is still in progress for the full v2.0 branch.
