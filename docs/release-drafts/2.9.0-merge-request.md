# darklab_shell 2.9.0 merge request

## Summary

- Adds a complete Project Assessment workflow from frozen Network, Web, API, TLS, and Combined cycles through evidence review, findings, retests, comparison, reports, and evidence-package handoff.
- Adds reviewable Assessment plans and durable batch execution with fair concurrency, recovery, cancellation, retries, child-run provenance, managed Nuclei preflight, and visibility in Projects, Status Monitor, History, notifications, and exports.
- Adds maintained Assessment actions, protected HTTP profiles, one-off Project probes, and optional ZAP and private OAST connectors without broadening the free-form run boundary.
- Extends the headless API and CLI across the supported Assessment, finding, evidence, risk, advisory, HTTP-profile, and probe workflows.
- Adds relationship-aware Atlas profiles, read-only Quick Lookup, richer report imports, typed scanner evidence, Web Surface capture review, exact version-to-advisory correlation, and bounded workflow fan-out.
- Makes DNS and other tool-output entity extraction record-aware so provider and resolver infrastructure no longer pollutes Atlas.
- Refreshes compatible runtimes, dependencies, CI images, and bundled tools; retires the local Nuclei compatibility patch; and makes dependency, image, APT-cache, browser, and container qualification more reliable.

The release turns Projects into a review and handoff workspace without weakening the existing owner, Team, command, scope, credential, artifact, or provider boundaries. The final review also tightened protected HTTP path enforcement, streamed request limits, external OSV time and concurrency bounds, and privacy-safe Assessment diagnostics.

The full Python and Vitest suites pass on the final-review branch. Source and bundle browser suites, real PostgreSQL coverage, and the deterministic container smoke corpus passed during pre-release qualification. Public DNS and HTTP smoke checks now run in a separate scheduled tier because their remote dependencies can time out even when the image is healthy.

## Risks

- Assessment cycles, evidence, connector jobs, workflow fan-out, and durable batches add schema and high-volume read paths. Normal startup migrations cover SQLite and PostgreSQL; quotas, paging, retention, indexes, and portable query-plan checks bound the new state.
- Approved plans can start many ordinary child runs. Instance, owner, batch, target, command, runtime, and retention limits remain configurable below fixed product ceilings, and every item is revalidated immediately before launch.
- The first startup with an empty managed Nuclei cache can make an outbound template request. Set both `NUCLEI_TEMPLATE_BOOTSTRAP_ENABLED=false` and `NUCLEI_TEMPLATE_REFRESH_ENABLED=false` when deployment policy requires offline cache maintenance.
- ZAP and private OAST depend on operator-managed services and network policy. Both remain disabled by default, use separate workers, preserve retry state, and keep credentials and private request material outside public records.
- Intrusive Assessment and probe actions remain disabled by default and still require fresh confirmation. Destructive actions aren't available.
- Entity-extraction fixes don't delete existing Atlas entities because an apparently noisy value may have valid provenance from another run. Operators can review and clean those links explicitly.
- Python, Go, dependencies, CI images, and bundled scanners move together in this release. OpenSSL remains on 3.6.3 and TLSX on 1.2.2 because newer upstream lines don't yet satisfy the image's compatibility and immutable-source requirements.
- The supported headless mutations are intentionally narrower than the browser. General Project administration, interactive Atlas intelligence, monitoring, Web Surface, grouped retests, and managed Nuclei refresh remain browser-owned workflows.
