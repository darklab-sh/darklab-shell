# darklab_shell v2.2 Release Notes

v2.2 focuses on project handoff and operator accountability: readable engagement reports, provenance-rich evidence exports, and an audit log for important actions.

## Highlights

- Project workspaces now include a Monitoring tab for project-linked watcher checks:
  - Monitor cards show current status, cadence, severity, top signals, latest fire, policy flags, linked targets, and current triage state.
  - The timeline keeps changed, recovered, failed, no-change, baseline-created, baseline-accepted, and paused events visible, even when an old baseline or current run has been deleted.
  - Available runs open in Run Details or Run Compare, while missing-run actions disable cleanly instead of hiding the stored fire summary.
  - Operators can pause or resume a monitor, queue a run, accept a new baseline, and mark changed or failed fires as acknowledged, expected, needs action, or resolved.
  - Project monitoring summaries expose changed, recovered, and failed counts, highest severity, bounded top changes, and links back to the full Monitoring payload for future digest workflows.
- The Project Report tab is now a complete engagement-report builder:
  - Write report metadata, executive summary, methodology, cover notes, and date ranges.
  - Choose included runs, targets, findings, and artifacts; toggle/reorder sections; save drafts; preview HTML; export a markdown/HTML archive; and use browser Print/PDF for a PDF copy.
  - Large project selectors page through runs, targets, findings, and artifacts while keeping All/None choices, filters, off-page manual selections, compact selected/excluded summaries, and bounded exclusions intact for preview and export.
  - View-only team members can preview and export the default readable report without gaining save, raw-output, or private-note access.
- Evidence packages and report archives now include richer export provenance:
  - Manifests record v2 archive metadata, selected evidence counts, redaction/private-note choices, and safe source summaries.
  - Package manifests also include bounded project-link provenance, import hints, and warnings when redaction, private-note exclusion, or unavailable artifacts limit future recreation.
  - Report archive provenance records selection filters, bounded exclusions, and resolved build-time counts for large report selections.
  - Package rows, previews, manifest views, and the Report tab show concise provenance summaries or compact source chips.
  - Package and report findings include readable target references and source context when export settings allow it; redacted output keeps relationship metadata while omitting target values.
  - Job-backed package and report exports include a safe audit correlation in the archive provenance without exposing session-derived details, and report completion logs/audit rows include safe selection counts and modes.
  - Report selector failures include safe paging and filter-state context in client-error logs without logging typed search text.
- `/diag/audit` is now an operator-facing audit log:
  - Important actions such as deletes, shares/exports, package/report builds, Atlas import apply, finding review, secret lifecycle, session-token lifecycle, team management, automation definition changes, and notification-channel config changes write bounded audit rows.
  - Audit details store safe ids, counts, labels, scope, and job/correlation metadata without raw tokens, file contents, imported row bodies, invite/recovery codes, raw automation commands, or notification secrets.
  - Operators can filter rows, inspect safe JSON details, follow available target/project links, and download capped CSV/JSON exports.
- Project users now get a scoped Activity tab inside Projects:
  - Personal owners and team members who can view the project can review safe project activity without access to the operator-wide diagnostics page.
  - Filters, pagination, collapsed details, mobile rows, and retention-aware empty states keep the trail readable for busy engagements.
  - Metadata edit sheets include a compact Recent activity panel for the item being edited, with a jump into the filtered Activity tab.
- Team owners and admins now get a scoped Activity subtab inside Options → Teams:
  - The view shows safe team-governance and shared-configuration rows without exposing operator-only request metadata.
  - Filters, paging, collapsed details, and retention-aware empty states match the Project Activity workflow.
  - The selected team overview includes a compact Recent activity preview before the full Activity subtab.
- Team-scoped audit rows truncate long identifiers inside the table so the Details column stays visible, and expanded details show a self-contained JSON envelope aligned back into the table.
- Project-scoped Findings Board refreshes now load each review column separately, so a large New backlog doesn't hide reviewed, false-positive, or follow-up findings.
- The shell now serves committed, content-hashed CSS and JavaScript bundles by default, while local development can still opt into source-file loading for edit-and-refresh work.
- SQLite deployments now auto-checkpoint and periodically truncate the WAL sidecar, keeping long-running containers from carrying an oversized `history.db-wal`.
- Team active-run checks use a Redis team index now, so shared-team streams, event replay, and kill checks don't slow down as unrelated active runs grow.
- Busy command and interactive PTY streams now keep run ownership alive without rewriting Redis metadata for every streamed frame.
- Startup now records run-output summary backfill status, so legacy runs with empty structured output or unreadable artifacts/previews are handled once instead of being retried on every restart.
- New full-output transcript artifacts are sharded under `run-output/ab/abcd/`, so growing artifact stores avoid one large flat directory without needing a migration for old files.
- History pages and run permalink JSON now reuse loaded label/note rows for label and note counts instead of running separate count queries for the same metadata.
- Static and vendor asset responses now use long-lived immutable browser caching while the main HTML route stays fresh.
- Shell, permalink, and diagnostics templates now render modular CSS through the asset manifest instead of walking the old `styles.css` import waterfall.
- Shell, permalink, diagnostics, lazy modules, fonts, favicon, and standalone vendor/static assets now have a committed bundle pipeline, so bundle-mode deployments can serve content-hashed build output from `app/static/build/` while local development keeps the source-file edit loop.
- The shell bootstrap and permalink viewer now use ESM entries, while diagnostics uses the same bundle pipeline for its CSS; the old shell core/feature classic bundle split has been retired.
- The frontend inventory now separates intentional browser globals, vendor globals, lazy placeholders, module API bridges, and compatibility reads, so the remaining `window.*` contracts are documented and reviewable.
- The frontend inventory tests now pin the remaining compatibility-boundary budgets, so any new bridge global, test hook, lazy placeholder, or allowlist growth has to be reviewed deliberately.
- More of the browser runtime now uses named ES module exports and explicit imports across shared helpers, tabs, output, runner, PTY, search, History, run comparison, Options panels, Atlas, Projects, Workflows, Schedules, Watchers, Status Monitor, and export helpers. Existing browser-global boundaries remain only where they are documented compatibility or runtime contracts.
- Lazy loaders now return loaded API objects for major on-demand surfaces, so callers can use the module they just loaded instead of reaching back through global state.
- Source-mode browser coverage now opens the high-risk lazy shell surfaces through normal controls, including Projects, Options panels, Command Registry, Workflows, Atlas, Status Monitor, history run details/compare, and PDF export.
- PDF export now lazy-loads the app PDF helper and the large `jspdf` vendor script on first use from the shell, History run details, or permalink viewer instead of loading them during first paint.
- ESM startup, lazy-asset, asset-manifest, asset-mode, build, and report-export job failures now log bounded context so operators can diagnose broken bundles or stalled report exports without raw query strings or job-file contents leaking into logs.
- The visual tour plus the shared Atlas tab helper/entity-row renderer, Atlas overlay/detail/mobile, Run Details modal, Findings Board, Project Activity tab, Project Artifacts tab, Project Packages tab, Project Report tab, Projects workspace modal, run comparison, Options subpanels, Command Registry modal, Workflows modal/editor/terminal command, PTY, Schedules, mobile background-run indicator, Status Monitor, and Watchers controllers now load only when those surfaces open, trimming normal shell startup JavaScript.
- Workflow editor buttons stay responsive before the Workflows controller has been downloaded; clicking them now loads the controller and opens the editor in one action.
- Interactive PTY keeps xterm, the fit addon, and xterm CSS lazy, and those lazy loads use content-hashed manifest URLs in bundle mode.
- In a cache-disabled local comparison against the pre-bundling checkout, initial app load requests dropped from 188 to 37 and total response time fell from about 660 ms to about 330 ms.
- Scanner-mode kill and API cancel requests now check that the stored PID still belongs to the original run before sending the sudo-backed process-group signal.
- The scheduler worker now runs daily retention pruning for expired runs, snapshots, run-output artifacts, and audit rows, so long-running containers keep retention current.
- Multi-worker startup now requires Redis. If `WEB_CONCURRENCY>1` and Redis is unavailable, the app fails fast instead of splitting active-run state across workers.
- Browser-owned built-in output saved through `/run/client` now goes through the normal metadata and redaction path before it becomes history, search text, or Atlas entity data.
- Server-side `sort` and `uniq` pipe helpers now bound their buffered input with `max_output_lines` and explain skipped lines with a `[post-filter]` notice.
- Dynamic app routes now have a baseline per-IP throttle before route matching, so broad HTTP scanners hitting random paths are rejected before they can crowd out normal browser, command start, or command kill requests. The default burst now gives the app's first page load enough room while the sustained per-minute cap still throttles unknown-path scans.
- The dependency version checker now reads urlscan-cli's calendar-versioned GitHub Releases, so it no longer mistakes the older `v0.0.6` Go module tag for the latest usable CLI release.
- The asset builder's cwd check now runs in the Node asset-check path, so Python-only CI jobs don't need Node just to run backend/docs tests.
- Projects and Files now close through the shared Escape/backdrop modal dismissal path again after the ESM migration, Shift+Option+F opens Files through an explicit Workspace import, and Option+Tab cycles tabs inside Options, Atlas, and Projects again.
- Mobile Projects controls now stop delegated click handling before async project hooks yield, so archived project expansion and artifact group collapse no longer toggle twice and appear unchanged.
- Sidebar workflow rows now use the same controller-owned Workflows opener as the rest of the app, preventing a scoped Workflows sheet from staying open and blocking the next source-mode lazy smoke action.
- Shodan autocomplete now follows the CLI's real scan shape: `shodan scan` suggests scan subcommands, and the target placeholder appears after `shodan scan submit`.
- Share snapshots created while a session token is active now keep that session on the `/share` request, and rejected share responses show the failure toast instead of copying a broken `...undefined` URL.
- Run Compare, History restore, and session-variable autocomplete now keep using the session-aware runtime fetch bridge after the ESM migration, so session-token and team-scope headers are preserved without relying on a legacy `window.apiFetch`.
