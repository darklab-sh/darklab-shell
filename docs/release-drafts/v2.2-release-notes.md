## Highlights

- Project report groundwork is in place: owner-scoped report drafts, a shipped report template catalog, report preview routes, async markdown/HTML archive exports, redaction-aware report composition for selected project runs, targets, findings, triage, and artifacts, and a Projects modal Report tab for editing, saving, previewing, exporting, and using browser Print/PDF.
- Evidence package and report archive manifests now use v2 metadata with compact provenance blocks that record build settings, selected entity ids/counts, redaction/private-note choices, and safe source summaries. Package rows, package previews, manifest previews, and the Report tab show concise provenance summaries or compact source chips, while package manifests also record safe project-link provenance for selected runs and targets plus import hints and warnings for future archive review/recreation flows.
- Finding output in packages and reports now shows readable target references, including target type/value when export settings allow it, source run, relationship source, and redacted fallback matches when the finding text mentions a project target without a stored target id. Redacted outputs keep the relationship metadata and omit the target-reference value field.
- Audit log groundwork is in place: the app can store bounded audit events with hashed session identity, optional team/member actor context, startup and guarded periodic retention pruning, a disabled-audit warning, and a per-event policy for fail-closed versus best-effort recording. History, snapshot, workspace-file write/move/delete, project-link, package/report export, download-ticket, Atlas entity, Atlas import apply, finding, secret lifecycle, session-token generation/revocation/migration, team-management, automation-definition, and notification-channel config actions now write bounded audit rows. Workspace file write/move rows store path, destination, count, and byte-size metadata without file contents; workspace file delete stays fail-closed. Atlas import apply rows store source, option, project, batch, and count metadata without imported row bodies. Session-token audit rows store only masked labels and hashes for token identity, with revocation and migration recorded fail-closed. Browser, API, and terminal team create/join/invite/revoke/member/recovery/archive flows record team audit rows without storing one-time invite or recovery codes. Browser, API/CLI, and terminal schedule/watch create/update/pause/resume/run-now/accept/delete flows record automation audit rows without raw command text, with schedule and watcher deletes recorded fail-closed. Browser, API/CLI, and terminal notification channel create/update/delete/test flows record config-change audit rows without webhook URLs, bot tokens, Pushover keys, SMTP passwords, or replacement secret values. `/diag/audit` lets operators filter with target-aware event hints, inspect, and download CSV/JSON exports of those rows.
- Team-scoped audit rows truncate long identifiers inside the table so the Details column stays visible, and expanded details show a self-contained JSON envelope aligned back into the table.
- Project-scoped Findings Board refreshes now load each review column separately, so a large New backlog doesn't hide reviewed, false-positive, or follow-up findings.
