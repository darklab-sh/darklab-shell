# v2.1 Release Merge Request

## Summary

v2.1 builds the **command knowledge layer**: a single discovery surface for
"what can I run?", "what does this tool do here?", and "what should I watch out
for in this web shell?", spanning the terminal built-ins, the autocomplete, and
the Command Registry modal. It also polishes the terminal chrome so the tab
strip reclaims space under pressure, and fixes a History drawer regression.

The registry (`commands.yaml`) stays the single source of truth; the new
`knowledge` fields are descriptive-only and never affect allow/deny policy,
validation, or execution.

### Added

- **Command knowledge schema** — optional `knowledge:` sub-fields per command
  (`notes`, `gotchas`, `safe_defaults`, `common_flags`, `artifact_behavior`),
  normalized and capped by the registry loader, merged across `.local` overlays
  (scalar-replace, list-extend with dedupe), projected onto the catalog and the
  `/commands/catalog/<root>` route.
- **`commands info` knowledge sections** and **`commands info <root> --json`**
  (deterministic single-line JSON for copy/debug).
- **`commands search <term>`** — catalog search across root, category,
  description, example values, and knowledge notes/gotchas; grouped by category;
  three-tier ranking (root prefix → category → other fields); feature-gated
  entries excluded.
- **Pipe-helpers discovery section** in `commands`/`commands --external` and the
  registry modal, plus a `pipe_helpers` array on `/commands/catalog`.
- **Output-aware `grep` autocomplete** — active-tab token suggestions
  (IPv4/IPv6, hostnames, CVE IDs, HTTP status codes, frequent words) gated to
  the `grep` pipe stage; never widens the allowed command surface.
- **Seeded knowledge** for twelve tools (`mtr`, `nmap`, `naabu`, `nuclei`,
  `gobuster`, `ffuf`, `testssl`, `dnsrecon`, `httpx`, `dnsx`, `subfinder`,
  `katana`), cross-checked against each tool's `workspace_flags`/
  `runtime_adaptations`.
- **Command outcome summaries** — deterministic browser-side summaries for
  supported `nmap`, `dig`, `nslookup`, `curl`, and `openssl s_client` output,
  plus an Options/`config` preference toggle and matching text/HTML/PDF/permalink
  export behavior.
- **Transcript noise classification foundation** — shared Python/browser
  `noise_kind` metadata for progress, status, and boilerplate lines, initial
  scanner-noise classifiers for ffuf, masscan, ProjectDiscovery tools, and
  nuclei, plus derived search-text, command-outcome, run-comparison, and package
  manifest filtering that preserves raw transcripts and keeps signal-bearing
  lines out of the noise path.
- **Config-backed evidence package preset catalog** — `app/conf/package_presets.yaml`
  now carries the shipped package preset metadata, with hot-reload, validation,
  operator override fallback, `package_presets_file` configuration support, and
  browser wizard rendering/defaults from the normalized catalog.
- **Bulk history export** — History bulk mode now offers **export text** and
  **export JSONL** for selected completed runs and snapshots; downloads keep
  skipped active/missing items visible and reuse the existing bulk-action session
  boundary.
- **Findings Board** — a larger desktop lane-based triage board now opens from
  the rail, Atlas toolbar, or Project Findings tab; cards reuse the existing
  finding review route for drag/drop and select-based review-state moves, while
  mobile Findings stays in the list flow.
- **Team-Mode** — durable session-token users can create teams, join by invite
  or recovery code, manage members/invites/recovery codes, archive/reactivate
  teams, and switch active personal/team scope from Options, the compact
  HUD/mobile selector, `/api/v1`, terminal `team`, and `darklab team ...`. Team
  scope covers runs, History, Run Details, recent values, Projects, Project
  targets, linked-run artifacts, evidence packages, deduplicated Atlas
  entities/findings, Atlas labels/notes/review/cached intel, shared workflows,
  schedules, watchers, notification channels/events, AI assists, package builds,
  explicit team secrets, provider readiness, and shareable team-owned run
  permalinks that keep team-private metadata behind valid team scope. The
  onboarding tour now includes Team-Mode in both the terminal walkthrough and
  the desktop visual carousel.
  Server-granted capability payloads drive the browser Teams panel, viewers stay
  read-only with clearer disabled controls and denial copy, History metadata
  edit and delete plus share snapshot controls lock in view-only scope across
  desktop and mobile, write-only Projects select mode stays unavailable,
  sole-owner self-demotion is locked until another owner exists, suppression,
  Atlas delete, and finding-review controls lock across desktop and mobile, and
  Findings Board drag/drop triage is disabled for viewer roles.
  Archived-team and recovery-code edge cases are guarded, newly issued one-time
  codes stay copyable from the Teams panel, the selector uses shared modal/UI
  primitives with clearly selectable rows, API/CLI config paths honor team
  scope, and team audit/logging uses safe actor context without exposing tokens,
  one-time codes, or secret values.
  Files routes, command-runtime rewrites, and terminal file built-ins now honor
  personal/team scope, keep `sess_*` and `team_*` roots separate, use
  owner-neutral workspace wording for file/quota errors, share team-file labels
  and notes, reload the Files panel on scope switches, rewrite tool input/output
  paths into the active workspace, redact hashed workspace paths from command
  output, keep project artifact previews and evidence package archives tied to
  the source run's workspace owner, let viewers read/download, and reserve
  write/move/delete/metadata actions for roles with `manage_workspace_files`.
  Archived teams stay readable in Files while file changes are blocked until
  reactivation.
- **Atlas auto-promote rules** — Project-owned rules can preview, create, edit,
  apply, delete, and automatically apply matching Atlas entities. Rules support
  exact, contains, wildcard, domain-suffix, and IPv4/IPv6 CIDR matching. Regex
  rules are unavailable and are rejected by the server. Project-level rule
  quotas and preview/apply caps keep broad rules bounded. The Project Entities
  tab exposes the Rules panel on desktop and mobile, keeps the editor preview
  requirement tied to match-affecting fields, uses shared confirm modals for
  apply and delete, supports source-run, command-root, first-seen, and suppressed
  entity filters, respects team view-only locks, and marks promoted rows with
  `Auto-promoted: <rule>`. Existing links stay when a rule is disabled, edited,
  or deleted. Auto-run rules watch future runs across the same
  personal/team scope and add matches to the project that owns the rule, even
  when another project is active for the command. For the active project,
  rule-matched entities are confirmed as rule-created links instead of waiting
  in the normal confirm/dismiss queue, and open Project modals refresh when a
  completed run adds links through a rule. Deleting a Project removes its saved
  rules with the rest of the Project-owned data. Rule route logs include safe
  rule shape and outcome counts without recording raw rule names or patterns,
  and the matching/apply service logs safe scan, quota, cap, and per-rule
  run-finalizer details for operator troubleshooting. Preview/apply API limits
  can request smaller windows, but they cannot exceed the configured
  auto-promote caps.
  Run-finalization summaries include
  affected project IDs, rule IDs, and bounded per-rule result counts. Browser
  failures in preview/apply/delete/save flows report safe client-error context
  with project/rule IDs.

### Changed

- **Bundled Postgres 18 service** — optional Compose, CI, and disposable test
  Postgres images now use `postgres:18-alpine`; the Compose volume mount follows
  the official Postgres 18 `/var/lib/postgresql` layout, and the docs describe
  export/import migration for older Compose-managed Postgres 17 volumes.
- **Auto-collapsing tab-bar chrome** — collapses to a magnifier + findings badge
  when tabs run low on room; state-independent decision (intrinsic widths) so it
  never oscillates; `»`/`«` toggle pins it open; choice persists.
- **Tighter toolbar labels** — line-number/timestamp toggles drop `: on`/`: off`
  (dot indicator shows state); search button no longer repeats the badge's
  findings count; timestamp mode still shown when active; `aria-pressed` added
  to both toggles.
- **Shared diff classifier foundation** — Watchers now consume tool-aware
  classifiers from `services.diff.classifiers`, with compatibility exports left
  under `services.watchers.classifiers`; `/history/compare` now also includes
  nmap port/service derived-change groups with source line indexes for
  transcript jump actions, plus URL/status derived-change groups for `httpx`,
  `ffuf`, `gobuster`, and `katana` output. Run Comparison renders those groups
  in a compact **Detected changes** section above the transcript diff.
- **Active Project HUD switcher** — the Active Project HUD chip now opens a
  compact searchable switcher instead of jumping straight into the Projects
  modal. The menu shows the active project or `No project`, lets users select or
  clear active-project focus through `/projects/active`, and keeps **Create
  project** plus **Open Projects** available for deeper project work. Recently
  activated projects stay scoped per personal/team context, search stays bounded
  server-side through `/projects?mode=switcher`, and team viewers can focus
  projects without unlocking project writes. The menu closes on project
  selection, HUD re-click, Escape, and terminal-area outside clicks.

### Fixed

- **Active Project HUD switcher dismissal** — the compact active-project
  switcher now hides when closed, closes when the HUD project cell is clicked
  again, and closes on terminal-area outside clicks even when that clicked
  surface stops event bubbling.
- **Fast-exiting interactive PTY replay** — Redis-backed PTY streams now replay
  any completed output and exit events before stale-run cleanup can prune an
  open-looking run, which keeps very short invalid interactive commands from
  losing the real tool error behind a missing-transcript fallback.
- **Redis 8 sidecar persistence** — the bundled Redis service now disables
  RDB/AOF persistence under its read-only root filesystem, keeping Redis aligned
  with its coordination/cache role and avoiding `MISCONF` write failures when
  Redis 8 attempts a default background save.
- **Run broker idle Redis timeouts** — Redis stream idle timeouts during quiet
  command output now emit stream heartbeats instead of ending the browser stream,
  including the Redis 8/redis-py path that reports the idle blocked-read as
  `ConnectionError("Timeout reading from socket")`, so slow-starting tools and
  smoke-test warmups still receive their terminal run event.
- **Elapsed timestamp gutter stability** — terminal rows now keep the elapsed
  timestamp gutter stable across blank prompts, command echoes, and full prefix
  resyncs, so previous rows don't appear to jump when output arrives.
- **History bulk-select drawer stability** — clicking **Select all** or **Clear**
  in History bulk mode no longer bubbles into document-level outside-click
  handlers after the toolbar re-renders.
- **Run Details schedule summary** — scheduled runs now show a readable
  `Scheduled run` or `Watcher run` label with the right owner action instead
  of wrapping the raw `sch_...` identifier inside the Summary card.
- **Schedules and Watchers shortcut focus** — opening either modal from the
  keyboard shortcut now moves focus into the modal without drawing a selected
  border, so typing does not leak into the terminal prompt and Escape closes the
  modal the same way it does after opening from the menu.
- **Scheduled active-run recovery** — scheduled and watcher-fired commands that
  are still running when the UI opens now stay in Status Monitor until the user
  chooses **Attach**, while Status Monitor still shows those runs for explicit
  attach/kill actions.
- **Workspace cleanup permissions** — expired session workspaces with
  scanner-created child folders are repaired before cleanup, and container
  startup now fixes immediate stale numeric-UID workspace children before the
  recursive repair pass without tripping the GNU `find` `{}` limit. Startup
  also repairs an existing `/workspaces` mount when local config points the app
  there without exporting `WORKSPACE_ROOT`. Empty unreadable direct child
  folders can be removed after repair failure, and startup repair failures now
  log the failed path and stage.
- **Atlas intel refresh feedback** — Refresh intel now shows a blocking progress
  panel while provider lookups run and disables duplicate refresh actions until
  the request finishes.
- **Grafana run-duration panel readability** — the top-5 average run-duration
  panel now uses a wider instant horizontal bar gauge over the selected dashboard
  range, so it stays capped at five tools and is easier to scan.

## Risks

- **Mostly additive.** The knowledge fields are descriptive-only and unknown
  keys are tolerated (lint-only), so malformed `.local` overlays cannot hard-fail
  registry loading.
- **Tab-bar chrome behavior** is the main UI-visible change; the collapse
  decision is state-independent (no oscillation) and search/line-number/timestamp
  controls remain reachable via shortcuts and the Options/mobile menus when
  collapsed.
- **`grep` output suggestions** read only the active tab's rendered output and
  are gated to the `grep` pipe stage — no new command roots are ever suggested.
- The permalink page keeps its verbose line-number/timestamp labels by design
  (separate read-only surface, no indicator dot).
