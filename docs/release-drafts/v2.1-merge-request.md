# v2.1 Release Merge Request

## Summary

v2.1 builds the **command knowledge layer**: a single discovery surface for
"what can I run?", "what does this tool do here?", and "what should I watch out
for in this web shell?", spanning the terminal built-ins, the autocomplete, and
the Command Registry modal. It also polishes the terminal chrome so the tab
strip reclaims space under pressure, and fixes a History drawer regression.

The registry (`commands.yaml`) stays the single source of truth; the new
`knowledge` fields are descriptive-only and never affect allow/deny policy,
validation, or execution.

### Added

- **Command knowledge schema** — optional `knowledge:` sub-fields per command
  (`notes`, `gotchas`, `safe_defaults`, `common_flags`, `artifact_behavior`),
  normalized and capped by the registry loader, merged across `.local` overlays
  (scalar-replace, list-extend with dedupe), projected onto the catalog and the
  `/commands/catalog/<root>` route.
- **`commands info` knowledge sections** and **`commands info <root> --json`**
  (deterministic single-line JSON for copy/debug).
- **`commands search <term>`** — catalog search across root, category,
  description, example values, and knowledge notes/gotchas; grouped by category;
  three-tier ranking (root prefix → category → other fields); feature-gated
  entries excluded.
- **Pipe-helpers discovery section** in `commands`/`commands --external` and the
  registry modal, plus a `pipe_helpers` array on `/commands/catalog`.
- **Output-aware `grep` autocomplete** — active-tab token suggestions
  (IPv4/IPv6, hostnames, CVE IDs, HTTP status codes, frequent words) gated to
  the `grep` pipe stage; never widens the allowed command surface.
- **Seeded knowledge** for twelve tools (`mtr`, `nmap`, `naabu`, `nuclei`,
  `gobuster`, `ffuf`, `testssl`, `dnsrecon`, `httpx`, `dnsx`, `subfinder`,
  `katana`), cross-checked against each tool's `workspace_flags`/
  `runtime_adaptations`.

### Changed

- **Auto-collapsing tab-bar chrome** — collapses to a magnifier + findings badge
  when tabs run low on room; state-independent decision (intrinsic widths) so it
  never oscillates; `»`/`«` toggle pins it open; choice persists.
- **Tighter toolbar labels** — line-number/timestamp toggles drop `: on`/`: off`
  (dot indicator shows state); search button no longer repeats the badge's
  findings count; timestamp mode still shown when active; `aria-pressed` added
  to both toggles.

### Fixed

- **History bulk-select drawer stability** — clicking **Select all** or **Clear**
  in History bulk mode no longer bubbles into document-level outside-click
  handlers after the toolbar re-renders.
- **Atlas intel refresh feedback** — Refresh intel now shows a blocking progress
  panel while provider lookups run and disables duplicate refresh actions until
  the request finishes.
- **Grafana run-duration panel readability** — the top-5 average run-duration
  panel now uses a wider instant horizontal bar gauge over the selected dashboard
  range, so it stays capped at five tools and is easier to scan.

## Validation

- `npm run test:pytest` — 1855 passed, 229 skipped.
- `npm run test:unit` (Vitest) — 1284 passed across 38 files (3 new:
  `command_registry.test.js`, `grep_output_suggestions.test.js`,
  `tabbar_chrome_collapse.test.js`).
- `npm run test:e2e` (Playwright) — 253 tests; affected specs re-run green
  (`history.spec.js`, `output.spec.js`, `ui.spec.js`, `timestamps.spec.js`).
- Combined documented total: 3,392 (1855 pytest + 1284 Vitest + 253 Playwright);
  the docs meta-test gate (`test_docs.py`) passes against the updated counts and
  appendix.
- Lint: ruff, eslint, stylelint, markdownlint, and yamllint clean on touched files.
- Manual browser check: `commands info`/`search`, the registry modal, `| grep`
  output suggestions, and the auto-collapsing chrome (including rail drag-resize).

## Risks

- **Mostly additive.** The knowledge fields are descriptive-only and unknown
  keys are tolerated (lint-only), so malformed `.local` overlays cannot hard-fail
  registry loading.
- **Tab-bar chrome behavior** is the main UI-visible change; the collapse
  decision is state-independent (no oscillation) and search/line-number/timestamp
  controls remain reachable via shortcuts and the Options/mobile menus when
  collapsed.
- **`grep` output suggestions** read only the active tab's rendered output and
  are gated to the `grep` pipe stage — no new command roots are ever suggested.
- The permalink page keeps its verbose line-number/timestamp labels by design
  (separate read-only surface, no indicator dot).
