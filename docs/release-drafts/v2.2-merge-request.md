# v2.2 Release Merge Request

## Summary

### Added

- Engagement report foundation: `project_reports`, `report_templates.yaml`, `report_templates_file`, report load/save/preview routes, async report archive export jobs, download tickets, report composition for selected runs, targets, findings, triage, and artifacts, plus a Projects modal Report tab for editing metadata, validating date ranges, choosing included items, saving drafts, previewing rendered HTML, exporting the markdown/HTML archive, and using browser Print/PDF. The draft keeps explicit None/All item selections distinct from the default include-all state, loads full finding/artifact lists before rendering report selection controls, resolves manual selections beyond the first bounded service page, and escapes Markdown table cells in the `.md` artifact.
- Evidence package and report archive manifests now use v2 metadata with compact provenance blocks for build settings, selected entity ids/counts, redaction/private-note choices, and safe source summaries. Package manifests also include opt-in project-link provenance for selected runs and targets without changing the default UI/API row payloads, plus import hints and warnings for package metadata, labels, notes, source links, target relationships, finding review state, redaction, private-note exclusion, and unavailable artifacts. Package rows, the package preview step, the manifest viewer, and the Report tab now show concise provenance summaries or compact source chips with older/not-recorded fallbacks.
- Package and report finding output now includes readable target references with target type/value when export settings allow it, source run, relationship source, stored confidence, and redaction-aware token fallback matching when a finding mentions a project target without a stored target id. Redacted outputs keep the relationship metadata and omit the target-reference value field.
