# v2.2 Release Merge Request

## Summary

v2.2 turns Project workspaces into a stronger handoff surface.

The release adds Project Monitoring, a full engagement-report builder, richer package/report provenance, and scoped audit views for operators, Projects, and Teams.

It also ships the new frontend bundle pipeline, operational hardening fixes, and CLI parity improvements for history and watcher workflows.

## Added

- Project Monitoring:
  - Adds explicit Project membership for watchers, Project inference from a single same-scope baseline run link, and cleanup when a Project is deleted.
  - Adds the Project workspace **Monitoring** tab with status cards, grouped monitor cards, filters, severity/top-signal summaries, and timeline rows.
  - Adds missing-run-safe Run Details and Compare actions, pause/resume/run-now actions, baseline acceptance, and fire triage controls.
  - Adds a **New monitor** action from the Monitoring tab, a Project selector in the Watchers modal, `darklab watch create --project`, and `darklab watch set-project`.
  - Adds watcher notification policy fields for ignored textual lines, repeated-change alert thresholds, and findings/entities/ports signal-class filters.
  - Adds persisted fire kind, state reason, acknowledgement state, acknowledgement notes, and bounded rollups for changed, recovered, failed, no-change, baseline-created, baseline-accepted, and paused events.
  - Adds `/projects/<id>/monitoring`, `/projects/<id>/monitoring/summary`, and `/projects/<id>/monitoring/fires/<fire_id>` browser routes with structured logs, safe audit metadata, and bounded client-error logging.

- Engagement report builder:
  - Adds the Project **Report** tab for report metadata, executive summary, methodology, cover notes, date ranges, section toggles/reordering, and evidence selection.
  - Adds draft save, HTML preview, markdown/HTML archive export, and browser Print/PDF from the Report tab.
  - Adds owner-scoped report drafts, optimistic concurrency, a shipped report template catalog, and operator-configured template choices when more than one template is available.
  - Adds server-paged selectors for runs, targets, findings, and artifacts.
  - Keeps dynamic All/None choices, filter-backed All selections, bounded exclusions, compact selection summaries, and off-page manual selections stable.
  - Adds report hardening for selector freshness, selector search drafts, finding/artifact search parity, selected-item summaries, target-reference labels, and query-load reduction.
  - Adds accessibility announcements, safe preview/export failure codes, and sanitized report logs.

- Richer package and report provenance:
  - Upgrades package and report archive manifests to v2 metadata with selected evidence counts, redaction/private-note choices, safe source summaries, project-link provenance, import hints, and bounded warnings.
  - Records report selection filters, bounded exclusions, and resolved build-time counts so large filter-backed selections stay explainable after export.
  - Shows concise provenance summaries and compact source chips in package rows, package previews, manifest previews, and the Report tab.
  - Includes readable package/report finding target references, source run, relationship source, stored confidence, and redaction-aware fallback matching.
  - Adds safe audit correlation to job-backed package and report archive provenance without exposing session-derived details.

- Audit log surface:
  - Adds the `audit_events` table, config defaults, recorder/query helpers, retention pruning, and event registry policies for fail-closed and best-effort audit rows.
  - Records bounded audit rows for history deletion, snapshots/redaction use, workspace file changes, project links, package/report builds, and download tickets.
  - Covers Atlas changes, finding review, secret lifecycle, session-token lifecycle, team management, automation definitions, and notification-channel config changes.
  - Adds the IP-gated `/diag/audit` viewer with filters, target-aware event hints, safe detail drawers, target/project links, and capped CSV/JSON downloads.
  - Adds scoped Project Activity and Team Activity views with filters, pagination, mobile rows, retention-aware empty states, and collapsed safe details.
  - Adds compact Recent activity panels to Project metadata edit sheets and the selected Team overview.

- Frontend asset bundle pipeline:
  - Adds committed, content-hashed CSS and JavaScript bundles under `app/static/build/`.
  - Adds manifest-backed Flask helpers for bundle and standalone static/vendor asset resolution, with bundle mode as the default runtime path and source mode kept for local edit-and-refresh work.
  - Moves shell, permalink, diagnostics, lazy surfaces, fonts, favicon, and standalone vendor/static assets onto the same manifest-backed path.
  - Lazy-loads major on-demand surfaces such as PDF export, Atlas, Projects, Watchers, Workflows, PTY, Schedules, Status Monitor, Run Details, run comparison, Options panels, Command Registry, and Findings Board.
  - Adds bounded diagnostics for startup, manifest, asset-mode, lazy-load, missing-export, ESM build, and report-export failures.
  - Adds frontend inventory checks so remaining browser-global compatibility boundaries stay documented and reviewable.

- CLI and API parity:
  - Adds `darklab history --type` with the same run-type choices as the browser History drawer.
  - Adds watcher policy create/update flags to `darklab watch`.
  - Updates `darklab watch info` and `darklab watch fires` to show fire kind, state reason, and acknowledgement state.
  - Updates `watch resume` to send the same explicit resume action as the browser.

## Fixed

- Notification HTTP DEBUG/WARN logs now strip webhook URL credentials by logging only the parsed host and optional port.
- Project Monitoring cards now render at most two per row on desktop, keep row heights consistent, and keep status/severity/acknowledgement/policy badges sized to their labels.
- The release branch checklist now calls out regenerating `docs/api-v1-openapi.json` after app version changes.
- `npm run lint:js` now covers the full `app/static/js/` source tree, and the pre-commit hook delegates to the same script.
- `markdownlint-cli2` dependency overrides clear the moderate npm audit findings without downgrading the lint runner.
- SQLite connections now set `wal_autocheckpoint=1000`, and Flask workers periodically run a guarded WAL truncate checkpoint.
- Redis-backed team active-run listings now use a `teamprocs:<team_id>` index instead of scanning every active-run metadata row.
- Brokered command and interactive PTY streams refresh owner liveness immediately, then throttle repeated refreshes on busy streams.
- Startup records run-output summary backfill status so unreadable or empty legacy runs are not retried on every restart.
- Full-output transcript artifacts now use hash-sharded paths, while existing flat artifacts still load and delete normally.
- History pages and run permalink JSON reuse loaded label/note rows for label and note counts.
- Static and vendor asset responses now use long-lived immutable browser caching while the main HTML route stays fresh.
- Shell, permalink, and diagnostics templates now render modular CSS through the asset manifest instead of the old `styles.css` import waterfall.
- Scanner-mode kill and API cancel requests verify the stored PID start time before signaling the process group.
- The scheduler worker runs daily retention pruning for expired runs, snapshots, run-output artifacts, and audit rows.
- Multi-worker startup now requires Redis and fails fast when `WEB_CONCURRENCY>1` cannot share active-run state.
- Dynamic app routes have a baseline per-IP throttle before route matching, protecting normal browser and command traffic from broad unknown-path scans.
- Browser-owned built-in output saved through `/run/client` now follows the normal metadata and redaction path before becoming history, search text, or Atlas entity data.
- Server-side `sort` and `uniq` helpers bound their buffered input with `max_output_lines` and emit a `[post-filter]` notice when lines are skipped.
- Run ownership and completion internals now share narrower helper paths across personal and team scopes.
- Built-in command ANSI rendering no longer shows stray underline/reset fragments.
- Team-scoped audit rows fit the table better, keeping the Details column visible at normal desktop widths.
- Project-scoped Findings Board refreshes load each review column independently, so large New backlogs do not hide other columns.
- urlscan-cli version checks now follow GitHub Releases instead of the stale Go module-proxy tag.
- Shodan autocomplete now follows the real `shodan scan` command shape.
- Projects and Files close through the shared Escape/backdrop modal dismissal path after the ESM migration.
- Mobile Projects controls no longer double-toggle when async project hooks yield.
- Sidebar workflow rows use the controller-owned Workflows opener.
- Share snapshots keep the active session token on `/share`, and rejected share responses show the normal failure toast.
- Run Compare, History restore, and session-variable autocomplete keep using the session-aware runtime fetch bridge.
- Official docs now use current-state wording consistently while preserving literal contract names.

## Risks

- `/diag/audit` is operator-wide and IP-gated. Deployments should keep `diagnostics_allowed_cidrs` narrow because allowed callers can see personal and team audit activity.
- Browser Print/PDF depends on the user's browser print engine, so PDF output should still be spot-checked before sending reports externally.
- Provenance is intentionally bounded and redaction-aware. It explains selected evidence and safe source context, but it is not a full raw copy of every source payload.
