# v2.2 Release Merge Request

## Summary

### Added

- Engagement report foundation: `project_reports`, `report_templates.yaml`, `report_templates_file`, report load/save/preview routes, async report archive export jobs, download tickets, report composition for selected runs, targets, findings, triage, and artifacts, plus a Projects modal Report tab for editing metadata, validating date ranges, choosing included items, saving drafts, previewing rendered HTML, exporting the markdown/HTML archive, and using browser Print/PDF. The draft keeps explicit None/All item selections distinct from the default include-all state, loads full finding/artifact lists before rendering report selection controls, resolves manual selections beyond the first bounded service page, and escapes Markdown table cells in the `.md` artifact.
- Evidence package and report archive manifests now use v2 metadata with compact provenance blocks for build settings, selected entity ids/counts, redaction/private-note choices, and safe source summaries. Package manifests also include opt-in project-link provenance for selected runs and targets without changing the default UI/API row payloads, plus import hints and warnings for package metadata, labels, notes, source links, target relationships, finding review state, redaction, private-note exclusion, and unavailable artifacts. Package rows, the package preview step, the manifest viewer, and the Report tab now show concise provenance summaries or compact source chips with older/not-recorded fallbacks.
- Package and report finding output now includes readable target references with target type/value when export settings allow it, source run, relationship source, stored confidence, and redaction-aware token fallback matching when a finding mentions a project target without a stored target id. Redacted outputs keep the relationship metadata and omit the target-reference value field.
- Audit log foundation: `audit_events`, a Postgres migration, config defaults, recorder/query helpers, startup and guarded periodic retention pruning, and an event registry for the audit surface. Session identities are hashed, details are bounded and allowlisted, sensitive events can fail closed, routine events can fall back to sanitized structured logs, and disabled audit logging warns once while letting product writes continue. History deletion, snapshots/redaction use, workspace file write/move/delete actions, project links, package/report builds, download tickets, Atlas entity suppression/deletion, Atlas import apply, finding review/suppression/deletion, secret lifecycle changes, session-token generation/revocation/migration, team-management actions, automation definition changes, and notification-channel config changes now record bounded audit rows with job/correlation ids for async work. Workspace file write/move rows are best-effort and store path, destination, count, and byte-size metadata without file contents; workspace file delete stays fail-closed. Atlas import apply rows store source, option, project, batch, and count metadata without imported row bodies. Session-token audit rows store only masked labels and hashes for token identity, with revocation and migration recorded fail-closed. Browser, API, and terminal team create/join/invite/revoke/member/recovery/archive flows record team audit rows without storing one-time invite or recovery codes. Browser, API/CLI, and terminal schedule/watch create/update/pause/resume/run-now/accept/delete flows record automation audit rows without raw command text, with schedule and watcher deletes recorded fail-closed. Browser, API/CLI, and terminal notification channel create/update/delete/test flows record config-change audit rows without webhook URLs, bot tokens, Pushover keys, SMTP passwords, or replacement secret values. `/diag/audit` gives operators an IP-gated audit viewer with target-aware event filter hints, safe detail drawers, available target/project links, and capped CSV/JSON downloads with truncation markers.

### Changed

### Fixed

- Team-scoped audit rows now truncate long scope and target identifiers inside the audit table, keep the Details column visible at normal desktop widths, and expand details rows with a self-contained JSON envelope aligned back into the table.
- Project-scoped Findings Board refreshes now load each review column separately, so large New backlogs do not starve reviewed, false-positive, or follow-up columns.
