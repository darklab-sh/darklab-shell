# darklab_shell 2.8.4 release notes

Version 2.8.4 brings planning, execution, evidence review, findings, retests, and final handoff together inside each Project. It also makes Atlas faster to navigate, gives scripts a much broader supported API and CLI, and cuts down the unrelated infrastructure that scanner output could previously save as entities.

## Project Assessment from plan to handoff

Projects can now start maintained Network, Web, API, TLS, and Combined Assessment cycles. Each cycle freezes its targets and checks so later catalog changes don't rewrite history. Assessors can see what is covered, needs review, lacks evidence, is excluded, or is unavailable; record manual decisions; link saved evidence; create and verify findings; prioritize shared fixes; queue compatible retests; compare completed cycles; and include the selected cycle in reports and evidence packages.

Assessment plans show the exact targets, commands, exclusions, safety policy, limits, expected coverage, and estimated duration before anything starts. Safe commands are selected by default, standard commands require separate confirmation, and intrusive or unsupported work stays out. Once approved, a durable batch keeps its place across reloads and restarts, shows child runs in Status Monitor and History, supports honest cancellation, and preserves completed evidence when another item fails or is retried.

Maintained actions cover common network, web, API, and TLS review. Reusable HTTP profiles apply saved request scope and limits while referring to darklab_shell Secrets and Files without copying credentials into visible plans. One-off Project probes use the same reviewed planning and launch checks when a full Assessment cycle isn't needed.

Optional ZAP and private OAST integrations are available for deployments that provide those services. They remain disabled by default. Intrusive actions also remain disabled by default, require fresh confirmation when enabled, and don't make destructive actions available.

## Atlas, evidence, and intelligence

Atlas profiles now lead with what darklab_shell observed: findings, related URLs and ports, services, source runs, Project context, monitoring changes, and saved provider intelligence. Focused Overview, Evidence, Findings, and Intel views use the same state on desktop and mobile.

Quick Lookup opens an exact saved hostname, IP address, or HTTP(S) URL without paging through Atlas. Use it from the desktop rail, mobile menu, or `Alt+Q` / `Option+Q`. Lookup is read-only: it doesn't create an entity, contact an intelligence provider, consume provider quota, or put the submitted value in structured logs.

Greenbone, Nessus, SARIF, CycloneDX, and compressed imports retain more typed, review-ready context. Nmap, HTTPx, DNSx, Dalfox, Schemathesis, ZAP, OAST, and other reviewed outputs can contribute bounded evidence only after their target and launch provenance are checked. Exact package and service versions can use stored OSV and NVD data, while EPSS and CISA KEV status now carries clearer source and freshness details in the browser and exports.

Web Surface adds a responsive gallery for verified HTTPx screenshots, full-image review, compatible-baseline comparisons, and package or report handoff without hiding missing or redacted artifacts.

## Cleaner entity extraction

Tool examples and supporting infrastructure are no longer treated like scanned assets. This includes SQLmap example sites, HTTPx model downloads and resolvers, selected DNS servers, testssl.sh documentation and third-party references, and WHOIS registrar or policy infrastructure.

`dig` and `nslookup` output is now interpreted as DNS records instead of a loose collection of hostnames and addresses. Relevant answers and alias chains remain available, while resolver echoes, SOA contacts, TXT references, DNSSEC material, reverse-zone owners, trace infrastructure, malformed owners, and negative lookup subjects stay out of Atlas. Complete run output, findings, search, comparison, and exports are unchanged. Existing entities aren't removed automatically because they may have legitimate evidence from another run.

## Headless automation

The versioned API and bundled CLI can manage the supported Assessment lifecycle, actions, batches, retries, cancellation, assessor-authored findings, typed evidence links, Nmap service evidence, HTTP profiles, EPSS/KEV status, exact-package OSV lookups, and Project probes. Commands use bounded input, stable text or structured output, explicit revisions, and confirmation flags that work in scripts as well as local terminals.

This isn't a copy of every browser action. General Project administration, interactive Atlas intelligence, monitoring, Web Surface, grouped retests, and managed Nuclei refresh remain browser-owned workflows.

## Operator and upgrade notes

- Normal startup applies the new SQLite or PostgreSQL migrations. No separate data-conversion command is required.
- Compose stores managed Nuclei templates in its persistent named volume. If the cache is empty, startup can make one bounded template update. To prohibit outbound template updates, set both `NUCLEI_TEMPLATE_BOOTSTRAP_ENABLED=false` and `NUCLEI_TEMPLATE_REFRESH_ENABLED=false`, then maintain the cache through your deployment process.
- ZAP and private OAST need their documented worker profiles, credentials, and network policy before their actions become available.
- Assessment command, concurrency, runtime, and retention limits can be lowered in configuration but can't be raised above the product ceilings.
- The container now uses Python 3.14.7 and Go 1.27, with refreshed compatible dependencies, CI images, and bundled scanners. OpenSSL stays on 3.6.3 and TLSX on 1.2.2 until newer upstream lines meet the image's compatibility and immutable-source requirements.
- Required container smoke tests no longer depend on public DNS or HTTP services. Those checks run in a separate scheduled tier so an external timeout doesn't misclassify a release image.
