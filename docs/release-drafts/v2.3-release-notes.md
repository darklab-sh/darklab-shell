# darklab_shell v2.3 Release Notes

v2.3 expands darklab_shell's external-tool and Project workflows: more recon tools are available in the container, their command registry entries understand Files-aware inputs and outputs, their structured output now feeds Command Findings and Atlas instead of staying as plain terminal text, and Projects can now summarize and notify on attack-surface changes.

## Highlights

- **More external tools in the image** — `tlsx`, `cdncheck`, `trufflehog`, `massdns`, and `puredns` are pinned in the Docker image and covered by container smoke checks.
- **Safer command registry support** — `tlsx`, `cdncheck`, TruffleHog, and puredns now have command metadata, autocomplete hints, help examples, workspace-aware file flags, and policy guardrails. TruffleHog scans are limited to managed workspace folders or HTTPS Git repositories, and puredns bruteforce uses explicit resolver files.
- **Structured findings and Atlas capture** — `tlsx -json`, `cdncheck -jsonl`, TruffleHog JSON, and puredns output can now create findings, warnings, summaries, and Atlas entities. TruffleHog secret material is redacted before transcript storage or finding persistence, and CDN/cloud/WAF rows stay as context rather than vulnerabilities.
- **Nuclei template provenance** — saved Nuclei output, Run Details restores, evidence package transcripts, and Nuclei JSONL Atlas imports now preserve where templates came from: the managed cache, workspace templates, pinned-looking clones, operator updates, or custom update directories.
- **App-native `jq` pipe helper** — `command | jq ...` now works through a small app-owned JSON/JSONL selector with field selection, array iteration, simple filters, compact/raw output modes, parser parity between browser and server paths, and input/output safety caps.
- **New app-native intel providers** — `intel ip`, `intel domain`, and `intel url` can use Shodan InternetDB, FOFA, and ZoomEye without adding vendor CLIs or SDKs. FOFA uses vault-backed email/key secrets and ZoomEye uses the regional API endpoint with resource-credit-aware status.
- **Project digest monitoring summaries** — Project Monitoring summaries now have the bounded window contract used by attack-surface digest notifications, so digest sends report changes since the last successful send instead of re-announcing the current dashboard snapshot.
- **Project digest settings** — Projects now have scoped digest settings storage for enabled state, cadence, explicit channels, quiet digests, and separate evaluated/sent timestamps.
- **Digest scheduler dispatch** — Enabled Project digest settings now create hidden scheduler jobs that evaluate bounded windows, queue selected notification channels, and advance the sent window only after delivery succeeds.
- **Project digest notification payloads** — Project digest notifications include compact project/window/count/severity/top-change details and Monitoring links, with `app_public_base_url` support for public worker-generated URLs.
- **Digest controls in Project Monitoring** — Project owners and eligible team roles can enable digests, choose cadence, select channels, and toggle quiet digests from the Monitoring tab while viewers see the settings read-only. Channel delivery history now shows digest project/window context for troubleshooting retries and dead letters.
- **Project Overview tab** — Projects now have an Overview tab that rolls up target findings, certificate status, cached intel, ports, services, and recent changes. Target rows can jump straight into filtered Entities or Findings views, and mobile Projects shows the same overview inside the detail sheet.

## Operator Notes

- FOFA search calls need `FOFA_EMAIL` plus `FOFA_KEY`, `FOFA_API_KEY`, `FOFA_APIKEY`, or `FOFA_TOKEN`, and the account needs an F-point balance.
- ZoomEye uses `ZOOMEYE_API_KEY` with `api.zoomeye.ai` and needs available resource credits.
- puredns support is intentionally scoped to `bruteforce` with the packaged DNS wordlist plus workspace-aware resolver and output flags.
- The `jq` helper is not the host `jq` binary and intentionally rejects arbitrary jq programs, shell escapes, joins, transforms, arithmetic, recursion, and file access.
- Project digest notifications use explicitly selected existing channels. Delivery deferrals, rate limits, muted channels, retries, and dead letters appear in the same per-channel **Deliveries** history used by other notifications.
