# darklab_shell

darklab_shell is a self-hosted browser shell for network diagnostics and security reconnaissance. The production image contains the application and its approved scanner toolchain, so operators can run a released stack without cloning or building the source repository.

Source, documentation, and release history: https://gitlab.com/darklab.sh/darklab_shell

Production installation starts from the versioned, checksummed setup files attached to each final GitLab release. The public Compose path uses immutable semantic-version OCI image indexes from `docker.io/darklabsh/darklab-shell`; Docker automatically selects the native Linux AMD64 or ARM64 child. `latest` is not part of the supported release flow. Release-candidate tags use `X.Y.Z-rc.N`, are intended for validation, and may be removed after testing. SELinux Docker and rootless Podman are verified separately against the AMD64 child.

## Install

Follow the [Quick Start](https://gitlab.com/darklab.sh/darklab_shell/-/blob/main/README.md#quick-start) to download and run the production Compose bundle. No source checkout or local image build is required.

The matching setup files, checksums, signature bundle, and deployment archive use the same version in GitLab's Generic Package Registry:


## Verify The Publisher

Protected GitLab tag pipelines keylessly sign this Docker Hub image index, the matching canonical GitLab registry index, every child manifest included in the release, and the release checksum manifest with Sigstore/Cosign.

Expected OIDC issuer:

```text
https://gitlab.com
```

Expected certificate identity regular expression:

```text
^https://gitlab\.com/darklab\.sh/darklab_shell//\.gitlab-ci\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-rc\.[0-9]+)?$
```

Verify an immutable image digest with:

```sh
cosign verify \
  --certificate-identity-regexp '^https://gitlab\.com/darklab\.sh/darklab_shell//\.gitlab-ci\.yml@refs/tags/v[0-9]+\.[0-9]+\.[0-9]+(-rc\.[0-9]+)?$' \
  --certificate-oidc-issuer 'https://gitlab.com' \
  'docker.io/darklabsh/darklab-shell@sha256:RELEASE_DIGEST'
```

Replace `RELEASE_DIGEST` with the canonical index digest recorded in that release's `release-manifest.json`. The GitLab and Docker Hub index references must report the same digest. The manifest's platform map separately records the child digest Docker selects on this host; use that value for local platform checks, not as a replacement for the signed index target above.
